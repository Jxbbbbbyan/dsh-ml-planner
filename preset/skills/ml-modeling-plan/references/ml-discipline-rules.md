# ml-discipline-rules — 管线级规则目录

> 本文件是 `ml-modeling-plan` 的**规则总目录**：按管线阶段 P0~P10 组织，每条规则带**唯一类别标签**与**强度**，
> 并写成"机理 → 工程落地 → 判定方式 → 违反的后果 → 语料反例"的完整推理链。
> 每条规则的依据都能回指语料 key（`3942513879_<msgid>_<itemidx>`），可回 `wechat-corpus/` 核对。
> 管线阶段图、门禁与调用关系见 `ml-pipeline-and-invocation.md`；本文件不重复那边的流程图。

## 0. 怎么用这个文件

1. **先按阶段定位**：先确认自己在 S0~S10 的哪一步（见 `ml-pipeline-and-invocation.md` §2），再按阶段码找到本文件对应小节（如 S2 → §4 P2）。
2. **再读规则**：每条规则的标题是祈使句，可**直接当勾选项**。`MUST` 违反即结论无效；`SHOULD` 违反必须在产物里显式声明理由。
3. **落到 `ML_BRIEF.md`**：把该阶段全部 `MUST` 规则的"工程落地"字段抄进 `ML_BRIEF.md` 对应栏目（问题类型 / 数据与标签 / 切分与泄漏 / 基线 / 评价指标 / 可解释性与上线口径）。
4. **验收怎么判**：每条规则的"判定方式"优先给可机检判据（断言、文件字段、图面数值范围）；给不出断言时给明确的人工判据，不接受"看起来没问题"。
5. **冲突怎么处理**：两条规则冲突时，按"违反的后果"更严重的一方优先；仍判不了就把冲突写进 `ML_BRIEF.md` 的"未测/冲突"栏，并**停在该阶段**，不得继续。

## 2. P0 · 问题定义与范围

**本阶段的目标与出口物**：把"要回答什么问题、在什么域上回答、用什么指标回答"写成可判定的契约，出口物是 `ML_BRIEF.md` 的"问题类型 + 适用域"两栏，以及一份带 key 的外部依据清单。本阶段不写任何训练代码。

### P0-01 · 开工前写死适用工况范围，并声明训练域之外一律不可信

- **类别 / 强度 / 适用模式**：`SCOPE` · `MUST` · `both`
- **机理**：模型学到的是**训练分布上的条件关系**，不是物理定律。工况、几何、边界条件、批次一变，该条件关系不再有约束力，误差不是"变大"而是**无界**。因此适用域不是说明性文字，而是所有指标的解释边界：离开该域，RMSE/AUC 都不构成对模型的陈述。
- **工程落地**：在 `ML_BRIEF.md` 的"问题类型"栏写死三行：训练工况枚举（含每工况样本数）、允许插值的区间 `interp_bounds`、明令禁止外推的轴 `no_extrap_axes`。任何画到训练域之外的预测图，必须画出训练域边界线并标注"域外不可信"。
- **判定方式**：可机检 —— 产物里存在 `applicability.json`（或 `ML_BRIEF.md` 同名小节），三个字段均非空；抽查任一预测图，若坐标范围超出 `interp_bounds` 而无边界线与标注，判不通过。
- **违反的后果**：结论无效且**不可归因** —— 读者会把"域外崩溃"读成"方法不行"或"模型不行"，而两者都不成立。
- **语料反例（带 key）**：`3942513879_2247500704_1` —— 该篇点明训练只用某几个工况、部署时是新工况，"分布已经变了，模型效果就可能掉很多"，应在契约里显式声明适用工况范围；`3942513879_2247500642_1` —— 预测被画到训练域 [−4,6] 之外（网格到 [−6,8]），域外预测均值与真值分离达 4 个单位，正文三点全部未提；`3942513879_2247500442_1` —— 该篇把"不擅长外推（超出训练数据范围就'懵'）"作为必须写清的适用边界。
- **正例（带 key）**：`3942513879_2247500442_1` —— "数据量不大、关系非线性明显、对外推要求不高"三条同时满足才推荐使用，写法克制且准确。
- **关联**：被 `P8-02` 依赖（上线口径引用同一份适用域）；与 `P0-02` 共同构成完整的"域"声明。

### P0-02 · 逐通道声明量纲、缩放方式与坐标范围

- **类别 / 强度 / 适用模式**：`SCOPE` · `MUST` · `both`
- **机理**：同一批数据里各通道量级可能差 3~6 个数量级。任何共享轴、共享距离、共享正则项的环节（距离度量、RBF 核、梯度下降、L1/L2 惩罚）都会被大量级通道支配，弱量级通道的信息在数值上被淹没而不报错。反向的失效同样存在：为了"统一尺度"而做全局缩放，会把物理量纲语义一起抹掉。
- **工程落地**：在 `ML_BRIEF.md` "数据与标签"栏列一张表：`通道名 | 物理量 | 单位 | 典型范围 | 缩放方式（逐通道/全局/不缩放）`。出图规范里强制记录每个子图的坐标范围与直方图分位数。
- **判定方式**：可机检 —— 该表存在且每行四列非空；抽查任一张分布对比图，若某个通道被压成贴地细线（四分位范围小于轴跨度的 1%）而无单独子图或分段展示，判不通过。
- **违反的后果**：结论**反转** —— 多通道对照实验的差异可能全部来自量级而非方法；图上"看不出差异"会被误读成"方法无差别"。
- **语料反例（带 key）**：`3942513879_2247500348_1` —— 栅格张量天然是"不同量纲通道共用一个张量"（位移 mm、应力 MPa、体积分数无量纲，量级差 3~6 个数量级），该文指出若不做逐通道处理，弱量级通道会被完全淹没；`3942513879_2247500059_1` —— income 的小提琴被一根从 0 直插到约 23 万的长尾拉爆，energy_MJ / friends / screen_min 三把琴被压成贴地细线；`3942513879_2247500520_1` —— 未缩放通道量纲达 ±5000，x 轴被拉得极宽，其余三条曲线被压成 x≈0 处的一条竖直线。
- **正例（带 key）**：`3942513879_2247502535_1` —— 明确点出"随机森林不需要标准化，不代表整个 Pipeline 都不受标准化影响"，这是把尺度敏感性当成逐步骤问题而不是模型属性的正确写法。
- **关联**：与 `P3-03`（尺度敏感步骤清单化）互为依赖；被 `P10-03` 依赖（图面范围可判读）。

### P0-03 · 先写可判定的契约，再写训练代码

- **类别 / 强度 / 适用模式**：`ENG` · `MUST` · `both`
- **机理**：事后补写的"结论"会把已经跑出来的数字反向解释成合规，而契约先行时任何一项缺失都会在动手前暴露。契约的作用不是文档，而是**把不可证伪的口头判断转换成开工前就必须给出数值的字段**（基线是谁、指标在哪算、切分单元是什么）。
- **工程落地**：`ML_BRIEF.md` 六栏（问题类型 / 数据与标签 / 切分与泄漏 / 基线 / 评价指标 / 可解释性与上线口径）全部有内容之前，不得创建训练脚本。契约里每一栏必须能被本文件的某条 `MUST` 规则勾选。
- **判定方式**：可机检 —— 训练脚本的 mtime 晚于 `ML_BRIEF.md` 的 mtime；`ML_BRIEF.md` 六栏无空栏；每个指标名后跟一个作用域限定。
- **违反的后果**：**无法归因** —— "先跑起来再看"的管线下，选型结论往往只是"A 先跑出高分"，换一个基线或换一份切分即翻转。
- **语料反例（带 key）**：`3942513879_2247502763_1` —— 该篇批判的流程正是"随便找一个 CSV → head() → 划分训练测试 → 随机森林/XGBoost/LightGBM 全跑一遍 → R² 0.92 / AUC 0.95 → 结束"；`3942513879_2247501353_1` —— "先看肘部、再结合业务定 K"属看图拍板，K/阈值应在契约里预先声明决策规则而非跑完图再补理由；`3942513879_2247501298_1` —— 全文节奏是"阶数固定为示例 + 超参直接给定 + 跑通即分享"，`TimeSeriesSplit` 导入即弃。
- **正例（带 key）**：`3942513879_2247500415_1` —— 原文在动手前就把前置处理约定写死（"标准化只在训练集上 fit，再应用到验证/测试集，避免数据泄漏"），并同时给出手工写法与 `Pipeline` 写法；`3942513879_2247500249_1` —— 六项契约的骨架在该篇中完整可见。
- **关联**：是 `P9-06`（契约写了必须执行）的前提；被本文件所有 `MUST` 规则的落地动作依赖。

### P0-04 · 每个结论绑定"适用域 / 报告域 / 指标"三件套

- **类别 / 强度 / 适用模式**：`METRIC` · `MUST` · `both`
- **机理**：同一个数字在不同子集上算出来含义完全不同。指标只在其计算集合上有定义，因此"F1 = 0.92"这类陈述若不带报告域，读者会自动把它外推到全域，从而高估。指标的作用域是**指标定义的一部分**，不是附注。
- **工程落地**：`ML_BRIEF.md` 的"评价指标"栏每个指标写三列：`指标名 | 计算集合（掩码/子集/工况） | 采样口径（样本级/单元级/算例级）`。报告里首次出现该数值处必须重复一次作用域短语（如"高置信参考区域上的 F1"）。
- **判定方式**：可机检 —— 解析结果表，每个指标行的作用域字段非空且非 "all"（除非脚本显式声明 `scope=full` 并给出该域样本数）。
- **违反的后果**：结论**虚高**且跨实验不可比 —— 换一个报告域就换一个分数，读者却以为看到的是同一个量。
- **语料反例（带 key）**：`3942513879_2247501933_1` —— 该篇明确要求把指标写成"模型在高置信参考区域上的分类性能"，不能说成全区域真实损伤识别精度；`3942513879_2247501038_1` —— 清洗把最难的极端目标从测试集里一并删掉，于是"清洗后指标更好"同时包含"模型更稳"与"考题变简单"两个原因；`3942513879_2247501464_1` —— 该篇只写"对角线越亮越好"，从图 6 反算出的准确率 69.0%、状态 1 召回 41.3% 正文一个都没报。
- **关联**：`P6-11`（不同测试集不可横比）是它在评估阶段的具体化；`P6-08`（指标必须落文）依赖它给出作用域。

### P0-05 · 效果措辞必须绑定数字，禁用无数字的评价

- **类别 / 强度 / 适用模式**：`EVIDENCE` · `SHOULD` · `both`
- **机理**："切得合理""效果不错""更稳"这类判断没有阈值，因而**不可证伪**，也无法在后续轮次里被对比或推翻。它会把一次未经检验的直觉固化成结论，并让下游引用失去可核对的对象。
- **工程落地**：报告与图注里凡出现"好/合理/更稳/明显改善"，必须同一句内给出数字与作用域。若对应的数字算过但没写，直接补；若没算，改成"未测量"。
- **判定方式**：可机检（正则）—— 检索"合理|不错|更稳|明显|较好"，命中行内若无数字则人工复核；`Test Accuracy` / `OOB Score` 等已计算量若未出现在正文任一处，判不通过。
- **违反的后果**：**不可归因** —— 后续优化失去基准，无法判断改动是否有效。
- **语料反例（带 key）**：`3942513879_2247502998_1` —— 正文称随机森林"能把双月牙切得比较合理"，而 `Test Accuracy` 与 `OOB Score` 都 print 了却一个都没写；`3942513879_2247501841_1` —— AUC 只有 0.7073，原文结论却是"模型依然能得到不错的判别效果"，且无基线对照。
- **关联**：与 `P10-01`（每条断言必须能指出证据）同源；`P4-06` 依赖它把"为什么选它"写成可核对项。

### P0-06 · 标题、推广话术与"通常"式表述不得作为方法依据

- **类别 / 强度 / 适用模式**：`EVIDENCE` · `SHOULD` · `both`
- **机理**：营销口径优化的目标是传播而非准确，其"结论"常常与自身正文的实测相反。把标题当依据会直接引入未经检验的断言；"通常""你很可能会看到"这类**预言式措辞**则是把通用经验伪装成本次实测，使得"不成立"也无需负责。
- **工程落地**：任何引用都必须落到**正文里可指认的位置与数字**；引用清单里为每条依据标注"实测 / 仅机制论述 / 仅目录条目"三档之一。产物中的效果陈述必须写成"本文实测 X → Y"。
- **判定方式**：人工判据 —— 依据清单中每条的档位已标注，"仅目录条目"一档不得出现在 `ML_BRIEF.md` 的选型理由里。
- **违反的后果**：**结论无效** —— 依据本身不存在，或依据只支持一个更弱的命题。
- **语料反例（带 key）**：`3942513879_2247501909_1` —— 标题写"讲透200个机器学习模型：随机森林、XGBoost、LSTM、Transformer"，正文 2511 字符里对这四个模型一字未讲；`3942513879_2247502838_1` —— 标题"最强总结！融合 Transformer+GNN+LSTM"暗示值得照抄，正文实测结论却是"复杂模型没打赢最朴素的持续性基线"；`3942513879_2247501735_1` —— 纯推广文，零案例、零代码、零指标，清单条目的存在不等于文中给出过任何验证。
- **关联**：`P4-03`（只在正文承诺的对照不算基线）是它在基线一栏的具体化；`P10-04`（图注与实现一致性）是它在出图一栏的具体化。

## 3. P1 · 数据与标签

**本阶段的目标与出口物**：写清"标签怎么来的、在哪一层定义、哪些量因此被禁止进输入、无标签区怎么表达"，出口物是 `ML_BRIEF.md` 的"数据与标签"栏 + 一份标签来源溯源表（含阈值、边界、离散化参数）。

### P1-01 · 标签即网格：切分单元与评估域不能也是网格

- **类别 / 强度 / 适用模式**：`SCOPE` · `MUST` · `fem-extra`
- **机理**：场量标签在空间上强相关，相邻单元的取值近似重复样本。按单元随机切分会把近似重复的单元分到训练与测试两侧，测试集因此不再是"新样本"，F1 会系统性虚高。切分必须发生在**物理对象层**（样件、算例、试件），栅格只是同一对象内部的采样。
- **工程落地**：切分的主键写死为 `specimen_id` / `case_id`，绝不用 `cell_id`。在 `ML_BRIEF.md` "切分与泄漏"栏写明切分单元与每个单元的样本数；同一算例的所有栅格必须同侧。
- **判定方式**：可机检 —— 断言 `set(train.specimen_id) ∩ set(test.specimen_id) == ∅`，且 `test.specimen_id` 覆盖的算例数 ≥ 2。仅断言 cell 不重叠不算通过。
- **违反的后果**：**指标虚高**，且虚高幅度不可估计；换到真正的新样件上指标会大幅回落，看起来像"过拟合"而实际上是切分错误。
- **语料反例（带 key）**：`3942513879_2247501933_1` —— 原文原话"训练集和测试集一定要按样件划分，不能把同一个冲击区域的像素随机分开，否则相邻位置过于相似，F1 很容易虚高"，并指出与"标签即网格"互补的一条：**标签是网格，但评估域与切分单元不能也是网格**；`3942513879_2247501409_1` —— 滑窗样本高度重叠而 `train_loader` 用 `shuffle=True`，随机打乱会让相邻窗口跨 train/val 边界混入。
- **关联**：`P2-08`（切分器选型）与 `P2-09`（近重复检测）是它的通用形式；`P1-10`（栅格化信息损失）与之并列构成"网格标签"的两条诚实性要求。
### P1-02 · 生成标签所用的物理量及其派生量不得进输入；原阈值法降级为基线

- **类别 / 强度 / 适用模式**：`SCOPE` · `MUST` · `both`
- **机理**：若标签由某个场量（峰峰值图、应力、位移）经阈值得到，而输入里又含该场量或其直接派生量，则模型只需复现划分规则即可拿高分 —— 这是把答案偷喂给模型的一种形式，与目标编码泄漏同源。阈值本身没有错，错在它同时又出现在特征侧。
- **工程落地**：`ML_BRIEF.md` "数据与标签"栏列出"标签来源量"名单（含派生量：梯度、极值、包络、统计量），并在"切分与泄漏"栏写一条显式排除：该名单的任一元素不得出现在最终特征矩阵中。原阈值规则**不删除**，而是降级为必须被超越的基线，与模型并排报指标。
- **判定方式**：可机检 —— 断言特征列名与"标签来源量"名单的交集为空（名单元素用规范化前缀匹配）；结果表里存在阈值法基线的行。
- **违反的后果**：**结论无效** —— 指标衡量的是"模型能否复现人写的规则"，不是"能否识别物理现象"。
- **语料反例（带 key）**：`3942513879_2247501933_1` —— 原文"如果标签来自峰峰值图，模型输入中又直接包含峰峰值，就可能存在标签泄漏"，处置是把峰峰值阈值法降为基线、主模型"尽量"用其他时域/频域/时频特征（注意原文用词是"可能""尽量"，本项目作为硬约束执行时是我们自行加强）；`3942513879_2247500104_1` —— 该篇直接用 RF 在训练集上的样本内预测当 NN 输入，造成训练/推理分布不一致。
- **关联**：与 `P2-03`（堆叠必须 OOF）、`P2-04`（训练/推理同分布口径）同族；被 `P4-03` 依赖（阈值法基线必须真的跑）。

### P1-03 · 跨物理量证据只能称"一致性验证"，不得称 ground truth

- **类别 / 强度 / 适用模式**：`SCOPE` · `MUST` · `both`
- **机理**：用另一个物理量（厚度图、老化特性、第二测量手段）去佐证标签，验证的是**两个量之间的一致性**，而不是标签的真值。命名决定了结论的边界：一旦写成 ground truth，后续所有误差指标都被读者理解为对真值的误差，误差来源也随之被掩盖。
- **工程落地**：`ML_BRIEF.md` 与报告里对第二物理量统一使用"跨物理量一致性验证"这一措辞；若产物中出现 `ground_truth` / `真值` 字段名指向该量，改名并在表里注明其物理来源与测量方式。
- **判定方式**：可机检（正则）—— 检索 `ground_truth|真值|gt_`，命中处必须指向独立获取的标签来源，指向第二物理量的命中判不通过。
- **违反的后果**：**结论无效** —— 把一致性误报为精度，读者会据此认为标签误差已被量化，实际误差仍未知。
- **语料反例（带 key）**：`3942513879_2247501933_1` —— 原文"厚度图不要称为真实标签，可以叫'跨物理量一致性验证'"；并进一步警告该文把第三章（硬分类 + F1）与第四章（概率图 + 不确定分析）当合理递进，但两章标签生成机制不同，**跨章的指标数值不可横比**。
- **关联**：与 `P0-04`（三件套）共同约束"数字意味着什么"；被 `P6-11` 依赖（不可横比的判定依据）。

### P1-04 · 做标签敏感性实验：扰动阈值/边界/分辨率后看结论是否翻转

- **类别 / 强度 / 适用模式**：`SCOPE` · `MUST` · `both`
- **机理**：标签由阈值、边界、插值方式、分辨率共同决定，这些参数是**人为选定的**，因此标签本身带有一层未量化的不确定性。若不扫这些参数，就无法区分"模型学到了物理现象"与"模型复现了人的一个特定划分"。结论在小扰动下翻转，说明它属于后者。
- **工程落地**：在"最小测试集"里固定一组扫描：损伤核心半径 / 健康区边界 / 划分阈值 / 栅格分辨率各取 3 档，报告各档下的主指标与差值。结果写成"结论在各档下是否保持同号且超过噪声"的一句话。
- **判定方式**：可机检 —— 结果表里存在 `label_sensitivity` 分组且组数 ≥ 3；每组的指标与阈值取值均有记录。
- **违反的后果**：**无法归因** —— 无法回答"F1 高，是模型识别出了损伤，还是只复现了你的划分规则"这一质疑。
- **语料反例（带 key）**：`3942513879_2247501933_1` —— 该文的"标签敏感性实验"（改变损伤核心半径、健康区边界、划分阈值）是它唯一接近参数扫描的机制，也是回应"人工标签是否主观"的正面手段；同一篇又指出该文三项实验设计**只给清单与目的，无任何数值、重复次数、统计检验**，这正是本案应避免的写法。
- **关联**：与 `P9-03`（单点不算结果）配套；`P6-07` 提供显著性判据。

### P1-05 · 离散化不确定性必须随样本携带

- **类别 / 强度 / 适用模式**：`SCOPE` · `MUST` · `fem-extra`
- **机理**：有限元输出值是离散化的函数：网格一改，同一物理位置的"真值"就变。因此标签误差不是一个全局常数，而是**逐样本、随网格参数变化**的量。丢掉它会让评估把离散误差全部归给模型，也会让不同分辨率的算例在数值上不可比。
- **工程落地**：每个样本的元数据里带 `mesh_resolution` / `element_size` / `solver_tolerance`；在"最小测试集"里选 1~2 个算例做网格加密对照（同一物理设定两档网格），把两者的标签差作为该样本的离散误差量级记录下来。
- **判定方式**：可机检 —— 样本元数据表中上述三个字段无缺失；存在至少一组"同物理设定、不同网格"的配对样本及其标签差值。
- **违反的后果**：**不可归因** —— 模型误差与离散误差混在一起，无法判断提升来自建模还是来自更细的网格。
- **语料反例（带 key）**：`3942513879_2247502947_1` —— 该篇被点出"求解器离散误差、代理模型误差、标签噪声"三类不确定性不能混算，且不要把"某模块带来提升"当作可迁移结论；`3942513879_2247501933_1` —— 该篇的标签由人工划分得到，原文承认"我不知道真值是多少"，其结论因此只能限定在报告域上。
- **关联**：被 `P8-04`（不确定性职责划分）依赖；与 `P6-03`（区间宽度）配套。

### P1-06 · 标签必须过守恒/可实现性门控，未收敛/非物理样本不进训练集

- **类别 / 强度 / 适用模式**：`SCOPE` · `MUST` · `fem-extra`
- **机理**：误差小不等于标签有效。一个求解未收敛、网格残缺或违反守恒/边界条件的场，可能在小范数误差下依然给出物理上不可实现的目标，用它训练等于让模型去拟合数值伪影。门控与精度是**两个独立判据**，前者不能用后者替代。
- **工程落地**：为每个样本记录求解状态（收敛标志、迭代残差、是否触发回退），并写三条入集条件：收敛、网格完整、守恒量偏差在阈值内。不满足的样本不删，而是带 `valid=false` 与原因码留在数据表里，训练集按该标志过滤。
- **判定方式**：可机检 —— 数据表含 `converged`（bool）与 `invalid_reason`（枚举/null）两列；断言进入训练的样本全部 `converged == True`，且被排除样本数与原因分布已写入报告。
- **违反的后果**：**结论无效** —— 模型在学数值伪影；同时被排除样本数不透明，数据规模无法复核。
- **语料反例（带 key）**：`3942513879_2247501029_1` —— 该篇指出有限元仿真数据会出现"求解未收敛 / 网格残缺 / 变量数量不定导致的大量缺失"，并把"缺失即信息"作为数据契约里的一条显式选项而非默认填充；`3942513879_2247500069_1` —— 该篇的缺失机制三分类（MCAR/MAR/MNAR）说明"删掉"与"填上"都必须先判定机制，不做机制判定就删样本会引入选择偏差。
- **关联**：与 `P1-08`（掩膜而非零填充）配套；被 `P6-01`（退化断言）依赖。

### P1-07 · 类别/区域/几何标识数组不得重采样到连续网格

- **类别 / 强度 / 适用模式**：`SCOPE` · `MUST` · `both`
- **机理**：整数区域标识是**类别值**，不是连续量。线性插值/平均/双线性重采样会把相邻两个区域 id 之间生成既不属于任何区域、也不对应任何物理位置的中间值。插值残差在数值上很小，因此这类错误不会报错，只会静默污染标签或特征。
- **工程落地**：为字段建一张类型表 `字段名 | 类型（连续/类别/标志）| 允许的重采样算子`。类别字段只允许最近邻、掩膜透传或"区域消失时置无效"，禁止任何带权平均。重采样后断言取值集合 ⊆ 原取值集合。
- **判定方式**：可机检 —— 断言 `set(resampled.unique()) ⊆ set(original.unique())`；类别字段重采样后出现非整数或新取值即判不通过。
- **违反的后果**：**结论无效** —— 训练/评估用到了物理上不存在的区域；错误不可见、不可回滚。
- **语料反例（带 key）**：`3942513879_2247501933_1` —— 该篇的标签结构要求明确区分"确定正 / 确定负 / 中间不贴标签且不参与训练"三区，中间区若被强行插值成某个类就等于制造了不存在的真值；`3942513879_2247501437_1` —— 该篇在压缩表示上直接用类中心代表原始点，作者意识到"一个子簇中心代表很多原始点"必须给 `KMeans` 传 `sample_weight`，即**类别/代表点在聚合时不能等权**，与不得插值是同一纪律的两个方向。
- **关联**：与 `P1-08`（掩膜）共同定义无标签区的表达方式；被 `P3-02`（统计量来源）依赖。

### P1-08 · 无标签区用掩膜而非零填充，缺失本身就是信息

- **类别 / 强度 / 适用模式**：`ENG` · `MUST` · `both`
- **机理**：零是一个**合法的物理取值**，因此零填充会产生"这里是有效的 0"与"这里没有数据"两种含义完全无法区分的输入。模型对这两者的梯度更新完全相同，于是缺失模式被误当成信号。掩膜把"有没有值"与"值是多少"拆成两路，才使缺失本身成为可学的信息。
- **工程落地**：输入张量携带一个与数据同形状的布尔掩膜通道（或缺失指示变量列），损失函数按掩膜加权；填充值只作为占位且必须与掩膜同时存在。若用支持原生缺失方向的模型（如 LightGBM/GBDT 路径），则写明用的是哪条路径。
- **判定方式**：可机检 —— 断言输入张量形状含 `(data, mask)` 两路，且 `assert mask.any() and not mask.all()`；类别数组断言 `values ⊆ classes ∪ {invalid}`。对树模型断言缺失未在前处理阶段被替换为 0。
- **违反的后果**：**结论反转** —— 缺失率高的子域会被模型读成"该物理量为 0"，该子域上的预测系统性偏移，且偏移方向随缺失率变化。
- **语料反例（带 key）**：`3942513879_2247500069_1` —— "加入缺失指示变量"被列为答法第 5 条，**代码里并没有真的加**（原文自相矛盾）；`3942513879_2247502838_1` —— 该篇明确"缺失值也不会被 GCN 自动补好，需要单独设计掩码、填补或缺失建模策略"。
- **正例（带 key）**：`3942513879_2247501959_1` —— GBDT 路径 `X_train.fillna(X_train.median())` + `X_test.fillna(X_train.median())`，只用训练集统计量填测试集，无泄漏；`3942513879_2247501029_1` —— LightGBM"每次划分自动学缺失值走左还是走右"是模型内的隐式处理，比全局填充保留更多信息。
- **关联**：被 `P3-02`（填补统计量来源）依赖；`P1-06` 的 `valid` 标志与掩膜语义必须一致。

### P1-09 · 可变数量输出用固定槽位 + 存在标志，并检查是否退化为 one-hot

- **类别 / 强度 / 适用模式**：`SCOPE` · `MUST` · `fem-extra`
- **机理**：对象数量可变时，网络输出维度必须固定，于是每个槽位需要一个"存在度"。若存在度没有约束，最小化重构误差会让它收敛到 0/1 —— 即模型放弃软分配，退化成"选一个槽位"，于是可变数量被硬编码成固定数量。这个退化过程是平滑的，损失曲线上看不出来，只能由存在度的分布检查发现。
- **工程落地**：输出张量形状写死为 `[B, K_max, C]` 外加 `[B, K_max]` 的存在标志；存在标志的监督信号来自真实数量（有对象→1，无→0），并在报告中输出存在度的直方图与"落在 (0.1, 0.9) 区间的槽位占比"。
- **判定方式**：可机检 —— 断言存在度张量的形状与槽位数一致；断言中间区间占比 > 0（若为 0，必须在结果里写明"存在度已退化为 one-hot"）；断言预测数量的分布与真实数量分布并排报告。
- **违反的后果**：**结论虚高且不可归因** —— 评测只看逐槽位误差时，退化的 one-hot 输出仍能拿到好看的重构指标。
- **语料反例（带 key）**：`3942513879_2247501636_1` —— 该篇的残差修正器被设计成接收展平后的高维输入收尾于单一标量 MSE，被点出在 FEM-ML 里"残差修正应当按槽位/按存在标志分别建模，不能照搬'单一标量 MSE + 一个 MLP 收尾'的做法"；`3942513879_2247501437_1` —— 槽位代表点不能等权看待，需要带权重/存在标志。
- **关联**：`P6-01`（退化断言）是它的评估侧对应规则；`P1-08`（掩膜语义）是它在输入侧的镜像。

### P1-10 · 栅格化/降采样必须报告分辨率与峰值保持率，并与结论并列

- **类别 / 强度 / 适用模式**：`SCOPE` · `MUST` · `fem-extra`
- **机理**：场量栅格化是有损压缩：包围盒外的部分、细网格上的局部分峰、陡峭梯度都会被抹掉。模型学的是**栅格化之后的场**，因此峰值是否被保留直接决定了模型能力的上限。若只报平均误差，栅格化损失会被算进模型误差，或反过来被平均掉而看不见。
- **工程落地**：记录 `网格分辨率 / 包围盒 / 栅格尺寸 / 插值核`；计算峰值保持率 `max(栅格场) / max(原场)` 与分位数保持率；把这两组数与主指标并列写在结果表首行相邻位置。
- **判定方式**：可机检 —— 断言结果表含 `peak_retention` 字段且取值已记录；断言存在一张"原场 vs 栅格场"的分位数对照（至少最大值与 95 分位）。栅格化前后有效秩/通道相关矩阵一并记录（若有效秩远小于节点数，必须写明"空间信息退化，复杂结构不会带来收益"）。
- **违反的后果**：**结论无效** —— 把栅格化损失报告成模型误差，或把"模型预测被压平"误判为"模型欠拟合"。
- **语料反例（带 key）**：`3942513879_2247500546_1` —— 真值范围 −9..27，预测值被压到 2..15，峰值被封顶到约 13–15 不再上升，正文完全没提；`3942513879_2247500249_1` —— 合成序列脉冲幅度到 13.5，模型从未预测出超过 9.0 的值，属"用过去均值外推"的收缩偏差；`3942513879_2247500364_1` —— 该篇给出可平移的教训：把栅格张量送进时空网络之前先算通道/节点间的相关矩阵或有效秩，有效秩远小于节点数说明空间信息退化。
- **关联**：与 `P0-02`（量纲/坐标范围）同为"输入表达"的诚实性要求；`P6-05`（峰值/Top-K）是它的评估侧对应规则。

## 4. P2 · 切分与泄漏

**本阶段的目标与出口物**：写清"训练/验证/测试按什么单元划分、谁允许看谁、每个统计量在哪一侧算"，出口物是 `ML_BRIEF.md` 的"切分与泄漏"栏 + 一份泄漏检查清单（逐项可断言）。

### P2-01 · 一切预处理必须晚于切分

- **类别 / 强度 / 适用模式**：`LEAK` · `MUST` · `both`
- **机理**：`fit` 是**信息提取**动作：均值/方差/分位数/主成分方向都会把全部样本（含测试样本）的分布信息编码进变换参数。用这份参数再变换训练集，训练样本已经"看过"测试集，测试集不再是留出集，泛化误差被系统性低估。
- **工程落地**：所有预处理步骤（缩放、编码、插补、特征选择、目标编码、降维）写进 `Pipeline`，由 `Pipeline` 在切分**内部**执行；训练脚本里禁止出现任何在全量 `X` 上的 `fit` / `fit_transform`。切片顺序固定为：读数据 → 切分 → `fit`(train) → `transform`(val/test)。
- **判定方式**：可机检 —— 断言 `X_scaler.n_samples_seen_ == len(X_train)`（或等价的 `len(scaler.n_samples_seen_)`）；断言脚本中不存在 `fit_transform(X)`（括号内为全量变量名）形式的调用。
- **违反的后果**：**指标虚高**，且虚高幅度随样本量减小而增大；测试集分数不再是对未见数据的估计。
- **语料反例（带 key）**：`3942513879_2247500038_1` —— 原文把错误写法直接贴出来（`X_scaled = scaler.fit_transform(X)` 然后才 `train_test_split`）；`3942513879_2247499999_1` —— `PCA(n_components=2).fit_transform(X)` 用的是含测试集的全量 X，属无监督预处理泄漏；`3942513879_2247500991_1` —— 同上形态，在切分前对全表 `fit_transform`。
- **正例（带 key）**：`3942513879_2247500020_1` —— PCA 只 `fit_transform(X_train)`、测试集用 `pca.transform(X_test)`；`3942513879_2247500069_1` —— `ColumnTransformer` + `Pipeline`，插补器只在训练折上 fit，被语料记为本档第一个完全正确、无泄漏的写法。
- **关联**：`P3-01`（入 Pipeline）是它的工程实现；`P2-11`（画图泄漏也禁止）是它的边界扩展。

### P2-02 · 超参、阈值与模型选择只能用训练/验证数据

- **类别 / 强度 / 适用模式**：`LEAK` · `MUST` · `both`
- **机理**：一旦用测试集做选择，最终报告的数字就是 **N 次尝试中的最优值**，即 best-of-N 统计量，其期望高于真实泛化性能。此时"测试集"在功能上已经变成验证集，项目失去了任何无偏估计。
- **工程落地**：切分至少三份：train / valid / test。所有搜索（网格、贝叶斯、早停、阈值、特征选择、早停轮数）只允许读 train+valid；test 只允许在最后一次推理中读取一次。阈值与工作点选定后冻结，写入产物。
- **判定方式**：可机检 —— 脚本中 `test` 相关变量出现次数为 1（末段评估）；断言报告的测试指标 ≤ 任何候选配置的验证指标均值 + 噪声带（出现"测试优于全部验证候选"必须给出解释，如网格行被 `pivot_table` 丢过）。
- **违反的后果**：**指标虚高**，且幅度不可估计 —— 报告的提升可能完全来自选择次数。
- **语料反例（带 key）**：`3942513879_2247500009_1` —— 原文第 1 条误区"只看测试集调参 = 把测试集也拿去训练决策，泛化能力被高估"；`3942513879_2247501925_1` —— 5 折 CV 选出配置后报出的测试 AUC 比任何配置的 CV 均值高 +0.031，与"选择与报告共用一套协议"不相容；`3942513879_2247500302_1` —— permutation importance 在固定阈值 0.5 下计算，且用的是已用于选阈值的测试集。
- **关联**：`P5-01`（边界 argmax）、`P5-02`（CV 与测试差值）、`P7-10`（解释量必须在未调参数据上算）都依赖它。

### P2-03 · 堆叠/残差/校正器的输入特征必须 OOF

- **类别 / 强度 / 适用模式**：`LEAK` · `MUST` · `both`
- **机理**：第二层模型的特征若来自第一层的**样本内**预测，则该特征几乎贴合标签（残差≈0），二层学到的是"样本内残差有多大"；推理时二层面对的却是真实预测误差。训练/推理两阶段的特征分布不同，二层的贡献无法解释，且一层的过拟合被原样传递。
- **工程落地**：所有层间特征用 out-of-fold 预测生成：K 折内每折用其余折训练、对本折预测，拼成全长的 OOF 向量作为二层输入。时间序列用滚动/前向链式 OOF，禁止用未来折。产物中记录折数与预测生成方式。
- **判定方式**：可机检 —— 断言二层特征列与标签的相关系数显著低于一层样本内预测与标签的相关系数（`corr(oof, y) < corr(in_sample, y)`）；断言 OOF 向量的构造日志里折数 ≥ 2。
- **违反的后果**：**指标虚高**，且融合/堆叠的收益方向可能反转 —— 二层在验证集上表现良好，上线后无增益。
- **语料反例（带 key）**：`3942513879_2247500118_1` —— 残差校正器的第 8 维输入正是 LSTM 在 t 时刻的预测，若由样本内预测给出，校正器学的是"样本内残差"，与推理时的多步预测残差不同分布；`3942513879_2247500104_1` —— 直接用 RF 在训练集上的样本内预测当 NN 输入；`3942513879_2247500204_1` —— 第一层残差在训练段用 in-sample 拟合值、测试段用 300 步 forecast，两种口径误差量级天然不同。
- **正例（带 key）**：`3942513879_2247500799_1` —— 目标均值编码带平滑且必须在交叉验证折内 fit（`(mean·count + α·global_mean)/(count + α)`），且实现为 Pipeline 的一环。
- **关联**：与 `P2-04`（同名特征同分布口径）互为表里；`P4-04`（消融）必须建立在正确的层间特征上。

### P2-04 · 训练期与推理期的同名特征必须同分布口径

- **类别 / 强度 / 适用模式**：`LEAK` · `MUST` · `both`
- **机理**：特征名相同不代表分布相同。样本内拟合值、样本外预测值、滑动统计、以及任何"用当前及未来窗口计算的量"，在训练段与推理段是**两个不同的随机变量**。模型会在训练段学会利用一个推理段不存在的低误差通道，表现为上线性能断崖。
- **工程落地**：为每个特征记录"生成时可用信息的上界"（时间戳/折内/是否用到未来），并在训练与推理两条路径上使用**同一段生成代码**（同一函数、同一参数），产物中记录生成函数的哈希或版本号。
- **判定方式**：可机检 —— 对每个特征计算训练段与推理段的分布距离（KS 或均值/方差比），超过阈值必须解释；断言特征生成函数在两条路径上是同一个符号（非复制粘贴两份）。
- **违反的后果**：**结论无效** —— 离线指标无法支撑上线判断；"融合更好"的结论可能全部来自一个训练期作弊通道。
- **语料反例（带 key）**：`3942513879_2247500278_1` —— 同一个 `arima_pred` 特征在训练期是 `arima_fit.predict()`（样本内，几乎贴合 y），测试期是 `arima_fit.forecast()`（样本外），被读为"本文所有失败的共同根因"，而文章强调的"数据泄漏"只覆盖了滞后特征不能用未来值这一种；`3942513879_2247501907_1` —— 该篇宣称 LSTM"抽象时间特征"，实际 `loss = loss_fn(output.squeeze(), y_train)`，是共享同一监督目标的堆叠。
- **关联**：与 `P2-06`（窗口延拓方式）配套；`P8-01`（上线复用参数）是它在部署侧的延伸。

### P2-05 · 非因果统计量必须先切时间边界再计算

- **类别 / 强度 / 适用模式**：`LEAK` · `MUST` · `both`
- **机理**：均值、方差、分位数、周期性分解、PCA 方向都是**跨时间聚合量**，它们的取值依赖被聚合的区间。在全序列上算再切分，等于让训练期的统计量看见测试期的数据；反过来，先切分再算则保证每一侧只用自己可见的历史。
- **工程落地**：切分作为**第一步**，之后一切按时间聚合的统计量只在该侧的索引上计算。趋势/季节分解这类非因果变换，必须写明拟合区间与是否按步重拟合（见 `P8-07`）。
- **判定方式**：可机检 —— 断言 `scaler.mean_` 只由 `train_index` 的行算出（重算一遍比对）；断言分解类对象带有 `fitted_on` 字段且等于或早于 train 边界。
- **违反的后果**：**指标虚高** —— 时间序列的泄漏幅度通常大于截面数据，因为未来信息对当前值的解释力最强。
- **语料反例（带 key）**：`3942513879_2247501409_1` —— Z-score 的 mean/std 是在**全时段含测试段**上统计的（典型统计量泄漏），且切分发生在特征工程之后；`3942513879_2247500289_1` —— `StandardScaler().fit_transform(fe.values)` 在全序列（含测试段）上拟合，而正文自己写着"标准化要用训练段拟合、测试段变换"。
- **关联**：`P2-01` 在时序上的强化版；`P2-07`（bfill）是同一类"未来信息倒灌"的另一个入口。

### P2-06 · 窗口化/滚动/自回归变换必须记录延拓方式与误差累积

- **类别 / 强度 / 适用模式**：`LEAK` · `MUST` · `both`
- **机理**：多步预测的滚动递推用**自己预测的值**续接上下文，误差按步累积，因此 1 步与 365 步的误差量级不可同日而语。此外训练期与推理期的窗口起点、填充方式、可见长度往往不同，形成隐性口径差。不记录延拓方式，任何"混合更优"的结论都无法归因。
- **工程落地**：为每个滚动量记录 `window / min_periods / 起点处理方式 / 是否用预测值续接 / 最大延拓步数`；区间带宽按 horizon 分别给出（见 `P6-12`）。训练期与推理期使用同一段窗口生成代码。
- **判定方式**：可机检 —— 任务元数据含 `horizon` 与 `rollout_mode` 字段；误差表按 horizon 分组（组数 = horizon 数），否则判不通过。
- **违反的后果**：**不可归因** —— 多步外推上的"更差"可能只是延拓方式不同，而不是模型不同。
- **语料反例（带 key）**：`3942513879_2247501529_1` —— Prophet 只在 train 上拟合后直接预测 val+test，ETS 在 test 阶段却用 train+val 重新拟合，LSTM 只用 train 残差训练却自回归滚出约 365 步残差，"混合更优"无法归因；`3942513879_2247500589_1` —— 递归外推在 365 步上完全失控，Hybrid 跑到 75–92 而实际中枢在 65，比两个组件都差；`3942513879_2247501409_1` —— 滑窗样本高度重叠而 `shuffle=True`。
- **关联**：与 `P2-10`（重拟合口径一致）共同保证对照可比；`P6-12`（带宽随 horizon）是它在指标侧的判据。

### P2-07 · 时序数据禁止 bfill 与任何形式的未来回填

- **类别 / 强度 / 适用模式**：`LEAK` · `MUST` · `both`
- **机理**：`bfill` 用**下一个观测值**填充当前缺失，方向上是把未来信息搬到过去。它在数据上只改动了少数行，因此既不会报错也不会显著改变统计量，却足以让模型在关键时间点提前"看到"答案 —— 这是最难自查的一类泄漏。
- **工程落地**：时序前处理只允许 `ffill`、显式丢弃、或按训练段统计量填充；`min_periods=1` 这类"不引入未来值"的写法应在契约里点明为允许做法。上线用的窗口统计量必须能在流式条件下逐步计算。
- **判定方式**：可机检（正则 + 人工复核）—— 检索 `bfill|backfill|fillna\(method=.*b`，「其余全为零」不算通过：命中处必须逐个确认为非时序或已改写。
- **违反的后果**：**指标虚高**，且虚高集中在缺口附近的时间点，恰好是这类任务最关心的区段。
- **语料反例（带 key）**：`3942513879_2247500893_1` —— `y_lag1`/`y_lag7` 用 `bfill` 填充会**把未来值填进缺失位**，在时序里是潜在泄漏点，时序里应只允许 `ffill` 或显式丢弃；`3942513879_2247500289_1` —— 所有 `rolling(...).bfill()` 都会把未来值回填到序列开头；`3942513879_2247500784_1` —— `resid_std_full = resid_std.reindex(df.index).ffill().bfill()` 把训练段估计的滚动标准差外推到测试段，形成**恒定带宽**。
- **关联**：`P2-05`（先切边界）与 `P2-04`（同分布口径）在时序上的具体表现；`P6-12` 直接引用本例的恒定带宽反例。

### P2-08 · 切分器按"测试集要模拟谁"选，并给出实测依据

- **类别 / 强度 / 适用模式**：`LEAK` · `MUST` · `both`
- **机理**：切分不是默认动作而是**问题建模**：测试集应模拟上线时真正面对的那批样本。开局/分组用 `GroupKFold`，未来预测用时间切分，类比例敏感用分层，样件/算例用分组切分。选错切分器，指标衡量的就是另一个任务。
- **工程落地**：在 `ML_BRIEF.md` "切分与泄漏"栏写一句"测试集要模拟谁"，并据此选定切分器；同时写清随机切分是否被允许及其理由。分层/分组若被用来"更接近原始分布"，必须给出实测（两方案在各侧的分布对照）。
- **判定方式**：可机检 —— 切分器的类名与上面那句陈述一致；断言测试集的最小群组数 ≥ 1，且时间切分下 `max(train_time) < min(test_time)`。
- **违反的后果**：**结论无效** —— 指标对应的任务与上线任务不同；也可能反向低估（测试集比上线难得多）。
- **语料反例（带 key）**：`3942513879_2247500704_1` —— 正文称随机拆分"可能有偏差"、分层"更接近原始数据"，实测两者在测试集上完全一致（0.78/0.22）、训练集只差 0.01，本数据不足以展示分层的必要性（**断言必须配实测**）；`3942513879_2247501298_1` —— 时序按 `[:1500]/[1500:1750]/[1750:]` 三段严格顺序切分的正面写法；`3942513879_2247501933_1` —— 按样件划分而非按像素。
- **正例（带 key）**：`3942513879_2247500415_1` —— `train_test_split(test_size=0.2, stratify=y_sr, random_state=42)`；`3942513879_2247501364_1` —— 70/30 后再对半切成 Val/Test 各 15% 且分层。
- **关联**：`P1-01`（按样件）是它在 fem 模式下的强制形式；`P4-02`（对照逐项对齐）要求所有对照用同一切分器。

### P2-09 · 近重复样本与重叠窗口必须先检测再切分

- **类别 / 强度 / 适用模式**：`LEAK` · `MUST` · `both`
- **机理**：滑窗、重采样、数据增强都会生成与原始样本高度相似的副本。副本跨切分边界时，测试集里出现的"新样本"在训练集里有几乎相同的对应物，模型只需查表。这类泄漏静默发生且幅度很大，因为近重复样本的指标贡献接近满分。
- **工程落地**：切分前做一次近重复检测（窗口重叠度、特征空间近邻、哈希/指纹），把相似样本归入同一组再切分；重叠窗口必须按窗口起点分组，禁止打乱。检测结果（重复对数及其阈值）写入产物。
- **判定方式**：可机检 —— 断言跨侧样本对的最大相似度低于阈值（如近邻距离大于组内典型距离）；断言窗口化数据的切分发生在窗口生成**之前**或用起点分组。
- **违反的后果**：**指标虚高**且分布随重复率变化 —— 重复率越高，测试分数越接近训练分数。
- **语料反例（带 key）**：`3942513879_2247501409_1` —— 滑窗样本高度重叠，`train_loader` 用 `shuffle=True`，相邻窗口会跨 train/val 边界混入，时序上更该用顺序或滚动切分；`3942513879_2247499999_1` —— 该篇把 OOB 这种不浪费样本的方案列为"切分与泄漏"契约的备选，说明切分粒度本身就是需要显式决策的对象。
- **关联**：与 `P1-01`（按样件）在原理上同源；`P4-07`（同一切分做消融）要求重复检测只做一次并复用。

### P2-10 · 所有对照的切分与再拟合口径必须完全一致

- **类别 / 强度 / 适用模式**：`LEAK` · `MUST` · `both`
- **机理**：模型之间的信息可得量若不同（一路看见整段、一路只能滚动递推），"更好"可以完全来自信息优势而非建模优势。同理，一路在测试期重拟合、一路不重拟合，两者的"训练量"也不同。对照实验的有效性来自**逐项等价**，不是来自并行列出。
- **工程落地**：写一张对照口径表：`方案 | 切分边界 | 是否重拟合 | 重拟合用到的数据 | 滚动/条件预测方式 | 迭代次数`。任何一列不同的两行不得直接比较，除非该列本身就是被研究变量。
- **判定方式**：可机检 —— 对照表每列非空；断言同一实验内所有方案的 `split_hash` 相同（同一切分索引）。
- **违反的后果**：**结论无效** —— 差异无法归因给模型；这类错误常表现为"融合模型更好"，实际是其中一路偷看了更多时间。
- **语料反例（带 key）**：`3942513879_2247500893_1` —— SARIMA 用 `get_prediction` 对整段验证/测试做（条件）预测，而 LSTM/XGBoost 走滚动递推，三路模型的时间信息可用性不同，融合后的"更好"可能部分来自 SARIMA 那一路看到了更多信息；`3942513879_2247500589_1` —— Prophet 只用 train 拟合一次，ETS 在测试期用 train+val 重拟合，两个组件的"信息量"不对等；`3942513879_2247501529_1` —— 三者测试集口径不同，所谓"混合更优"无法归因。
- **关联**：`P4-02`（逐项对齐）是它在模型选择阶段的一般化；`P2-02`（选择协议）保证口径一致之后的选择仍然干净。

### P2-11 · "只为画图"的泄漏同样禁止

- **类别 / 强度 / 适用模式**：`LEAK` · `MUST` · `both`
- **机理**：画图代码与训练代码共享同一批变量和同一个会话，一旦允许例外，例外就会沿着复制粘贴进入正式流程。更直接的问题是：用测试集拟合的变换画出来的图，会被当作"数据的样子"写进结论，从而影响对切分与方法的判断。
- **工程落地**：可视化脚本的 `fit` 作用域与训练脚本相同（只 fit 训练集，测试集用同参数 `transform`）；若确实需要"看全量分布"，在图上显式标注"含测试集，仅用于展示，不参与任何建模决策"，并把它放进单独的探针脚本。
- **判定方式**：可机检 —— 断言可视化脚本中不存在全量 `fit`；存在例外时断言其输出文件带 `probe_only` 标记且未被结果表引用。
- **违反的后果**：**无法归因** —— 展示性泄漏污染对数据的判断，并会在下一轮被"合法化"进训练代码。
- **语料反例（带 key）**：`3942513879_2247500104_1` —— `PCA.fit_transform(X_test_s)` 在测试集上 fit（虽然只用于画图，不参与训练），该文被读为"允许'只是为了画图'的泄漏，就会有人把画图的代码搬进正式流程，契约应一刀切禁止"；`3942513879_2247501018_1` —— 该篇 `StandardScaler` 对整个 X（含测试点）拟合，当时无划分故无泄漏，但迁移到有划分的项目时必须只在训练集 fit。
- **正例（带 key）**：`3942513879_2247500348_1` —— 可视化环节的 scaler 也只在训练集 fit（代码注释显式说明）。
- **关联**：`P3-01`（预处理入 Pipeline）是它的工程解法 —— 封装之后画图与训练自动共享同一份已拟合参数。

## 5. P3 · 预处理与特征

**本阶段的目标与出口物**：把每个变换的"作用对象、拟合范围、量纲影响"写成可执行的一步，出口物是预处理 Pipeline 的序列化文件 + 一张 `通道/步骤 | 尺度敏感 | fit 作用域` 清单。

### P3-01 · 全部预处理封装进 Pipeline 并序列化落盘

- **类别 / 强度 / 适用模式**：`ENG` · `MUST` · `both`
- **机理**：手工 `fit` / `transform` 有两条必然风险：交叉验证内部仍会按全折拟合（折内泄漏），以及训练与推理两侧各写一遍导致口径漂移。`Pipeline` 把两者**结构性地**绑在一起 —— 交叉验证时每折自动重新 `fit`，推理时调用同一个已拟合对象。
- **工程落地**：所有变换（缩放、编码、插补、降维、特征选择、目标编码）作为 `Pipeline` / `ColumnTransformer` 的步骤；训练结束后把整个 Pipeline 用 `pickle`/`joblib` 落盘，推理脚本只允许 `load` 后 `transform`/`predict`，不得重建预处理器。
- **判定方式**：可机检 —— 产物目录存在 `pipeline.joblib`（或等价文件）；断言 `pickle.load(...)` 后的对象模块路径与训练脚本中构造的类一致；断言推理脚本中不存在 `StandardScaler(`/`PCA(` 等构造调用。
- **违反的后果**：**不可复现 + 指标虚高** —— CV 内泄漏让每折的验证分数虚高，两侧手写不一致让上线的输入分布与训练不同。
- **语料反例（带 key）**：`3942513879_2247500059_1` —— 缩放器虽然只在训练集 fit，但**未涉及 `Pipeline` 封装**，手动 fit/transform 在 CV 内仍可能泄漏；`3942513879_2247500038_1` —— 该篇被读为"工程上更稳的是把 scaler 塞进 Pipeline 一起做 CV（否则 CV 内仍有泄漏风险，文中也未提）"。
- **正例（带 key）**：`3942513879_2247500069_1` —— `ColumnTransformer` + `Pipeline`，插补器只在训练折上 fit；`3942513879_2247500259_1` —— 用 Pipeline 把预处理与模型焊死，训练/推理口径天然一致；`3942513879_2247500520_1` —— scaler → clf 串接；`3942513879_2247503077_1` —— `StandardScaler` 放进 Pipeline 再交给 `ElasticNetCV`，标准化统计量只在每折训练部分估计。
- **关联**：`P2-01`（晚于切分）的工程实现；`P8-01`（上线复用参数）要求落盘的正是这个对象。

### P3-02 · 填补/编码/缩放统计量只来自训练集

- **类别 / 强度 / 适用模式**：`ENG` · `MUST` · `both`
- **机理**：填充值、类别频率、目标均值都是**从数据估计出来的参数**，与模型权重同属"训练产物"。用全量估计再用到验证/测试侧，就是把测试集信息注入特征；其中目标编码类特征泄漏最重，因为它直接用了标签。
- **工程落地**：填补统计量取 `X_train` 的均值/中位数/众数并保存；类别编码用 `handle_unknown='ignore'`；任何"按类别统计标签"的特征必须带平滑项且在折内 fit（形式：`(mean·count + α·global_mean)/(count + α)`）。
- **判定方式**：可机检 —— 断言 `encoder.categories_` 由训练集唯一值构成（与 `np.unique(X_train[col])` 比对）；断言目标编码器的 `fit` 调用位于折循环内部。
- **违反的后果**：**指标虚高**；目标编码类泄漏尤其严重，因为标签统计量对测试样本标签有直接依赖。
- **语料反例（带 key）**：`3942513879_2247501959_1` 的反面情形是"两个差异同时变化"导致结论不可归因（该篇的正确样板见下）；`3942513879_2247501409_1` —— Z-score 的 mean/std 在全时段（含测试段）统计；`3942513879_2247500895_1` —— 该篇的标题点出的失败模式就是"训练集炸裂 / 验证集崩掉"＝目标编码把答案偷喂给了模型。
- **正例（带 key）**：`3942513879_2247501959_1` —— `X_train.fillna(X_train.median())` + `X_test.fillna(X_train.median())`，只用训练集统计量填测试集；`3942513879_2247500799_1` —— 目标均值编码必须带平滑且必须在交叉验证折内 fit，"本项目若做任何按类别统计标签的特征（如按工况统计平均应力），必须照此实现"；`3942513879_2247500104_1` —— `OneHotEncoder.fit(rf_train_leaf)` 只在训练集上 fit。
- **关联**：`P2-01` / `P2-03` 在参数层面的具体化；`P1-08`（缺失即信息）决定填充是否是最优处置。

### P3-03 · 尺度敏感步骤必须清单化

- **类别 / 强度 / 适用模式**：`ENG` · `MUST` · `both`
- **机理**："树模型不需要标准化"是关于**划分点**的结论，不是关于整条管线的结论。一旦管线里出现距离、梯度、正则项、PDE 残差、邻域算子、插值核等任一环节，尺度就会重新进入模型。尺度敏感是**逐步骤属性**，把它当成模型属性会漏掉一半通道。
- **工程落地**：在 `ML_BRIEF.md` "数据与标签"栏列一张表：`步骤 | 是否尺度敏感 | 处理方式`。至少覆盖：距离/核方法、梯度类优化、L1/L2 正则、PCA/降维、缺失填充（按距离或均值）、邻域/图算子、损失中的物理残差项。
- **判定方式**：可机检 —— 表存在且覆盖上述七类步骤；断言 `是否尺度敏感 = 是` 的行均有对应的缩放动作或显式豁免理由。
- **违反的后果**：**结论反转** —— 尺度敏感步骤在未标准化输入上失效（核矩阵退化为近单位阵、损失被单一通道支配），而树模型部分的表现正常，整体看起来"部分有效"。
- **语料反例（带 key）**：`3942513879_2247502535_1` 被语料标注为最高价值的一条：本文点明"随机森林不需要标准化，不代表整个 Pipeline 都不受标准化影响"，并指出栅格张量的归一化尺度会直接改变物理量纲，一旦插入任何尺度敏感步骤，理论上的"尺度无关"就不再成立；`3942513879_2247500415_1` —— 基于距离（KNN/KMeans）、基于梯度（线性/逻辑回归、NN、SVM）、带正则（L1/L2）、PCA 都必须标准化；`3942513879_2247502221_1` —— 栅格特征里不同通道取值范围差异极大，任何基于距离的模型/度量都必须在标准化口径下做。
- **正例（带 key）**：`3942513879_2247500348_1` —— §04"常见问题"八条中第 ② 条"树模型通常不需要标准化"与第 ⑥ 条"在线推理必须复用同一个 scaler（保存均值/方差）"并列，正是把尺度问题拆到步骤层面的写法。
- **关联**：`P0-02`（量纲声明）是它的前置；`P5-07`（超参量级依据）是它的下游。

### P3-04 · 预处理收益必须实测，禁用预言式措辞

- **类别 / 强度 / 适用模式**：`ENG` · `MUST` · `both`
- **机理**：预处理的效果依赖数据本身（分布、离群比例、尺度结构），不存在普适的"应当更好"。用"你很可能会看到"这类预言句写结论，等于把**通用经验当成实测结果**；当实测与之相反时，叙事会覆盖数据。
- **工程落地**：每个预处理方案必须给出"不处理 / 处理"两组在同一输入上的实测指标差值，并写明结论方向。措辞统一为"本文实测 X → Y"；若差值在噪声范围内，必须写"无显著差异"。
- **判定方式**：可机检 —— 结果表里每个预处理方案存在对应的 `baseline_none` 行；断言报告中没有出现 `你很可能会看到|通常会|往往能` 修饰实测结论的句式。
- **违反的后果**：**结论反转** —— 实测变差却被写成变好，读者据错误方向继续加码。
- **语料反例（带 key）**：`3942513879_2247500661_1` —— 图 5 实测 `KMeans @ RAW Silhouette=0.880` > `KMeans @ MIN-MAX Silhouette=0.746`（Min-Max 让聚类变差约 15%），而正文写的是"你很可能会看到 Min-Max 后聚类的轮廓系数更高"，是"正文与自有数据打架"最直接的案例；`3942513879_2247500770_1` —— 实测 MinMax 在含极端异常值的数据上明显偏差（KNN 0.715、Logistic 0.790），正文却把五个缩放器并列称"都会显著改善"；`3942513879_2247500520_1` —— KDE 与决策边界两张图实际没有承载它们声称要传达的信息。
- **正例（带 key）**：`3942513879_2247500661_1` —— 该篇的"同一批样本 + 同一随机种子 + 只切换预处理"的 A/B 对照设计本身是值得吸收的（六组图全部基于同一份数据）；`3942513879_2247500259_1` —— 主动注入 1% 极端离群来检验"稳健缩放抗离群"的主张，即**主动造出能证伪自己结论的样本**。
- **关联**：与 `P4-04`（消融）同源 —— 预处理也是一种"组件"；`P6-10`（指标恰好相同必须复核）是它的诊断触发条件。

### P3-05 · 同一变换只拟合一次并复用

- **类别 / 强度 / 适用模式**：`ENG` · `SHOULD` · `both`
- **机理**：同一变换被独立拟合多次，会产生多个"参数几乎相同但数值不完全相同"的对象。一旦求解器含随机成分（随机 SVD、随机初始化）或数据版本有微小差异，多个对象之间就不一致，训练用的与评估用的可能是不同的变换。
- **工程落地**：一个变换对应一个对象，训练、验证、可视化、上线全部复用；若确实需要不同维度（如 2D/3D 投影），从同一个已拟合对象切片或使用同一个 `components_` 的前 k 行。
- **判定方式**：可机检 —— 断言脚本中 `PCA(`/`TruncatedSVD(` 等构造调用次数为 1（或每个用途显式注册一次并记录原因）。
- **违反的后果**：**不可复现** —— 同一份代码两次运行可能给出不同投影，图与指标不再一一对应。
- **语料反例（带 key）**：`3942513879_2247500530_1` —— `pca_full` / `pca_2d` / `pca_3d` 三次独立拟合同一条流水线，属冗余且埋下不一致风险（若加了随机 SVD 求解器，三者结果可能不同）。
- **正例（带 key）**：`3942513879_2247500704_1` —— PCA 严格区分 `pca.fit_transform(X_train_scaled)` / `pca.transform(X_test_scaled)`，语料注出"本条极易被忽略"。
- **关联**：`P3-01`（入 Pipeline）天然满足本条；`P9-07`（死代码）常与本条同时出现。

### P3-06 · 降维/压缩必须给"压缩维度 → 原始物理量"的归因，并用 y 复核判别力

- **类别 / 强度 / 适用模式**：`ENG` · `MUST` · `both`
- **机理**：PCA 优化的是**总方差**，与是否可分无关。方差最大的方向可能正是类别完全混叠的方向；反之有效秩低（真低秩）也不等于低维可分。因此压缩的可交付性必须由两件事保证：能翻译回原始物理量，以及在标签上验证判别力是否保留。
- **工程落地**：产出载荷热力图（`components_` → 原始通道）与"每个主成分对应哪些区域/哪些物理场"的文字归因；同时报告压缩前后在同一评估协议下的主指标差值。降低维度后若类别混叠加剧，必须写进结论而不是只报累计方差。
- **判定方式**：可机检 —— 产物含载荷图文件；结果表含 `before_dim_reduction` 与 `after_dim_reduction` 两行同指标；断言累计方差曲线图上标注了选定 k 的决策点（阈值线 + k 竖线）。
- **违反的后果**：**结论无效** —— "降维有用"只有方差证据、没有任务证据；在 fem 模式下载荷不可回溯意味着压缩结果不可交付。
- **语料反例（带 key）**：`3942513879_2247500327_1` —— 正文说"数据在某个方向上分得越开，我们越能分辨它们的差别"，而图 4 显示 PC1（EVR=0.32，方差最大）上三类完全混叠，判别信息几乎全在 PC2/PC3；同一篇还指出文章自己列为选 k 准则之一的"下游效果"被完全跳过，整篇没有一条"PCA 有用"的量化证据；`3942513879_2247500177_1` —— "真低秩"不等于"低维可分"（5 维真结构前 2 个主成分不能分离 4 个群）；`3942513879_2247500661_1` —— RAW 尺度下 PC2 解释 0.00 方差（数据塌到 1 维），是信息表达退化，正文把它归因为"PCA 对尺度敏感"。
- **正例（带 key）**：`3942513879_2247500530_1` —— 用 `pca.components_` 载荷热力图把无监督降维的每个主成分翻译回原始特征，语料建议"任何降维/自编码器/特征压缩步骤，都要产出'压缩维度 → 原始物理量'的载荷/归因图"；`3942513879_2247500327_1` —— "累计方差 + 阈值线 + k 竖线 + 高亮散点"四件套把"为什么选这个 k"固定在图上。
- **关联**：被 `P4-04` 依赖（降维收益必须消融）；`P7-09`（线性基分量幅度图）是它在可解释性上的同一动作。

### P3-07 · 合成/仿真数据必须先自检是否退化；加噪必须发生在标签生成之后

- **类别 / 强度 / 适用模式**：`ENG` · `MUST` · `both`
- **机理**：合成数据的结论仅在"该数据本身不退化"时才有意义。若各维簇心同向递增，数据本质是一维的，任何尺度/方法的差异都会被压平；若噪声加在打标签之前，噪声只是把点连同其标签一起搬动，贝叶斯误差仍为 0，**难度没有增加**。这两种情形都会让对照实验得出"无差别"的假结论。
- **工程落地**：生成数据后先看谱（PCA 解释方差、有效秩）与簇心矩阵，确认不存在单维塌缩；造难度必须在打标签之后再加噪，或对边界附近样本按比例翻转标签。生成参数（centers / 标准差 / 样本量 / seed）全部写进 `ML_BRIEF.md`。
- **判定方式**：可机检 —— 断言生成数据的 PCA 第二主成分解释方差 > 阈值；断言噪声注入代码的位置晚于标签计算（同一函数内标签赋值在前、加噪在后）；断言四种生成参数均已记录。
- **违反的后果**：**结论无效** —— 对照实验在退化数据上做，"哪个尺度都容易分对"，结论不可推广。
- **语料反例（带 key）**：`3942513879_2247500661_1` —— 六个特征的簇心在所有维度上同向递增，因此数据本质上是 1 维的，图 3 左图实测 `Explained Var: 1.00, 0.00` 就是铁证，在这样的数据上讨论"Min-Max 让 KMeans 更好/更差"意义有限；`3942513879_2247501051_1` —— 代码注释写"少量均匀噪声，增强拟合难度"，但 X_noisy 加噪后才算半径、再按该半径打标签 ⇒ 标签是特征的确定性函数、贝叶斯误差为 0，实证是默认超参的基线 SVM 就画出与理论圆几乎完全重合的边界、调参后在 2000 条测试集上零错分；`3942513879_2247502936_1` —— 输入空间增强破坏了标签语义（螺旋数据的类别身份就是 θ 扇区），导致"强增强最差、少数类最受伤"。
- **正例（带 key）**：`3942513879_2247501353_1` —— 人造数据必须把 centers / 标准差 / 样本量 / seed 全部固定并写进 ML_BRIEF。
- **关联**：与 `P3-04`（实测而非预言）互补；`P1-04`（标签敏感性）是它的真实数据版本。

## 6. P4 · 基线与模型选择

**本阶段的目标与出口物**：先把"最笨但必须被超越的方案"跑出来，再谈选型；出口物是 `ML_BRIEF.md` 的"基线与模型选择"栏（含对照口径表、消融清单、成本约束）。

### P4-01 · 先跑平凡基线并与模型并排报告

- **类别 / 强度 / 适用模式**：`BASE` · `MUST` · `both`
- **机理**：任何指标都必须有参照物。多数类基线的准确率在类不均衡时可以高得惊人，持续性基线在缓变序列上是强基线。没有基线，模型分数只是**一个孤立的数**，无法判断是"学到了东西"还是"任务本身容易"。
- **工程落地**：默认基线清单（按任务类型取用）：多数类 / 随机 / 上一时刻值 / 滑动平均 / 线性回归或逻辑回归 / 滞后特征 + Ridge。基线必须真的跑出数值，并与模型写在同一张表的相邻行。
- **判定方式**：可机检 —— 结果表存在基线行且指标列非空；断言基线与其对应模型的评估协议（切分、指标、作用域）完全一致。
- **违反的后果**：**结论无效** —— 无法判断提升来自模型还是来自任务难度；读者会把"任务容易"读成"模型好"。
- **语料反例（带 key）**：`3942513879_2247500249_1` —— 正文给了天真基线 Naïve 的概念与"在许多序列上是强基线，应与之对比"的要求，但**代码只计算 MSE，也真的没有跑基线做对照**；`3942513879_2247501420_1` —— 全文没有给任何基线（如均值预测、线性回归）的数值，只有 KNN 四个点横向比较；`3942513879_2247501841_1` —— AUC 0.7073 被写成"不错的判别效果"，未与"均值填补 + 同参数模型"对比。
- **正例（带 key）**：`3942513879_2247502451_1` —— 明确要求 Logistic Regression 作为基线并给出量化门槛（LR 0.82 vs XGBoost 0.85，为 0.01~0.03 的提升上复杂模型是否必要）；`3942513879_2247501589_1` —— 先建简单基线（前一时刻值、滑动平均、线性回归、ARIMA、随机森林、XGBoost）再上 LSTM/ST-RNN，否则"说不清提升来自模型还是数据处理方式"；`3942513879_2247501156_1` —— 把"基线（线性回归）+ 强模型（GBR）"成对跑并同时报 train/test 的 MSE/MAE/R²。
- **关联**：`P1-02`（阈值法降为基线）要求同一清单里包含领域基线；`P4-05`（预算对等）保证基线不是陪跑。

### P4-02 · 对照必须逐项对齐

- **类别 / 强度 / 适用模式**：`BASE` · `MUST` · `both`
- **机理**：对照实验的因果解释力来自"只有一个变量不同"。深度、填充方式、迭代数、重训口径、可见信息量任意一项不同，"A 比 B 好"就无法归因给算法本身 —— 而这类差异在代码里非常自然（顺手给主角多设了几个参数）。
- **工程落地**：写一张对照口径表（见 `P2-10`），每列一个控制变量：`深度 / 特征填充 / 正则 / 迭代预算 / 学习率 / 重拟合范围 / 滚动方式`。任何一列在两组间不同且**不是研究目标**时，必须补齐或明确声明该列为混杂因素。
- **判定方式**：可机检 —— 对照表每列非空；断言同一实验内两组的关键结构超参（如 `max_depth`）在同一字典里赋值，而非分散在各处硬编码。
- **违反的后果**：**结论无效** —— 提升无法归因；这类错误最危险之处在于数字看起来完全正常。
- **语料反例（带 key）**：`3942513879_2247501959_1` —— GBDT `max_depth=3` 而 XGBoost `max_depth=4`，GBDT 吃中位数填充后的数据、XGBoost 吃原始 NaN 数据，两个差异同时变化，"XGBoost 更好"无法归因给算法本身；本项目任何"基线 vs 新方法"的对比必须逐项对齐（深度、填充、预算、迭代数）；`3942513879_2247500415_1` —— 图 3 的 SVM 对比不干净：两组都用 `gamma='scale'` 而该值耦合于特征方差，未标准化时方差≈10⁵量级、标准化后≈1，等效 gamma 相差数个数量级且 `C` 未重调，差异混合了"尺度变化"与"超参被动变化"两个因素。
- **关联**：`P2-10`（切分/重拟合一致）是它在数据侧的对应；`P4-05`（预算对等）是它在调参侧的对应。

### P4-03 · 只在正文承诺的对照不算基线

- **类别 / 强度 / 适用模式**：`BASE` · `MUST` · `both`
- **机理**：把"应当对比 X"写进正文、却不运行 X，会让读者在阅读时把 X 的缺席补成 X 已被比较。更隐蔽的版本是 import 了模型却从未使用 —— 代码看上去"考虑过"这个对照。契约要求的是一条**运行记录**，不是一句意图声明。
- **工程落地**：`ML_BRIEF.md` 的基线清单里每一项对应一条可运行的评估调用；若某基线因预算/数据不可得而不做，写"不做的原因"并把它列入"未测"栏，而不是保留在承诺列表里。
- **判定方式**：可机检 —— 断言基线清单中每个模型名在运行日志里出现且带指标输出；断言没有"已 import 但从未实例化"的模型类。
- **违反的后果**：**结论无效** —— 论文/报告层面看起来被比较过，实际没有，"X 更弱"是断言而非结果。
- **语料反例（带 key）**：`3942513879_2247501118_1` —— 标题承诺 RF vs ET 对照，实验里只跑了 Extra Trees，随机森林根本没训练，"对照"停留在文字层面；`3942513879_2247500799_1` —— `RandomForestClassifier` import 了但未使用，正文 04/06 节反复讲"树模型更鲁棒""模型与编码的匹配"，但没有跑任何树模型；`3942513879_2247500249_1` —— 天真基线只在正文说"应与之对比"，代码没有真的跑。
- **关联**：`P9-06`（契约写了必须执行）是它在工程记录侧的同一条纪律；`P0-05`（措辞必须绑数字）防止"承诺"被读成"结论"。

### P4-04 · 融合/降维/编码的收益必须做"去掉该组件"的消融

- **类别 / 强度 / 适用模式**：`BASE` · `MUST` · `both`
- **机理**：多组件模型的总表现是各组件贡献的叠加，而某些组件的边际贡献可能为 0 甚至为负（融合的权重校准不当会让分量互相打架）。不做逐组件消融，就无法排除"整块模型其实只等价于其中最简单的一支"这一解释。
- **工程落地**：消融按 2^k 阶梯设计并**在同一切分与随机种子**下执行（见 `P4-07`）：朴素基线 → 单支 → 双支 → 完整模型。每档报同指标与差值；对降维/编码类组件，额外跑"去掉该组件的同族模型"。
- **判定方式**：可机检 —— 存在 ≥ 3 档消融结果行且切分哈希相同；断言完整模型与最强单支的指标差值及其区间已记录（差值为正但不超噪声时必须写明"无显著差异"）。
- **违反的后果**：**结论无效** —— 标题里的"融合"实际没有产出；复杂度的成本被算进结果而不被质疑。
- **语料反例（带 key）**：`3942513879_2247502513_1` —— 图 2 右的特征重要性显示模型 79% 的重要性集中在 `y_lag1`+`y_lag2`（自身历史），PCA 主成分贡献很小，直接反驳了标题"PCA 与 XGBoost 融合"的必要性，而文中提出的"再和不使用 PCA 的 XGBoost 做一次对比"没有做；`3942513879_2247500327_1` —— 降维前后没有做任何下游对照；`3942513879_2247501471_1` —— 全文没有任何 baseline（无 ARIMA/Prophet/朴素滞后均值对照），无法判断 GRU+注意力+Transformer 融合相对单分支到底有没有增益；`3942513879_2247502133_1` —— 无验证集、无多种子、无基线对照（不跑单 Transformer / 单 LSTM），"融合更强"没有证据支撑。
- **正例（带 key）**：`3942513879_2247502838_1` —— 给出可用的消融清单：持续性基线 / 只有 LSTM / GCN+LSTM / GCN+Transformer / 完整融合 + 多随机种子 + 滚动回测 + 误差稳定程度；`3942513879_2247502630_1` —— 五档消融阶梯（朴素 → 仅原始序列 CNN → +Transformer → +小波 → +FFT）并要求"在相同时间切分和随机种子下做消融，结论才站得住"。
- **关联**：`P4-07`（同切分同种子）是前提；`P3-06`（降维判别力复核）是它在降维上的具体动作。

### P4-05 · 基线与主角的调参预算必须对等

- **类别 / 强度 / 适用模式**：`BASE` · `MUST` · `both`
- **机理**：把一个**未调好**的基线拿来对比，得到的差值混合了"方法更好"与"基线被欠训练"两个原因。这类比较的收益方向由预算分配决定，而不是由方法决定；把主角换成基线、预算对调，结论常常翻转。
- **工程落地**：为每个参战方案给出等价的预算（迭代上限、搜索格子大小、候选数、训练轮数），并在产物里写出每个方案实际消耗的预算；另需一个"默认参数的同一模型"作为对照，用来衡量调参本身值不值。
- **判定方式**：可机检 —— 结果表含 `budget` 列（如 `n_trials` / `epochs`），断言各方案预算同量级（比值不超过约定倍数）；断言存在 baseline-default 行。
- **违反的后果**：**结论反转** —— 换一次预算分配，胜负关系可能反过来。
- **语料反例（带 key）**：`3942513879_2247501773_1` —— GRU 的验证损失在 7 个 epoch 内持续上升（0.69→0.76）而训练损失只降到 0.58，属典型的"基线没调好就被拿来对比"，若 GRU 换更小 lr 或更长训练，"Transformer 完胜"的结论未必成立；`3942513879_2247501884_1` —— 只有 KRR 被调参，MA/KNN/Poly 的参数是随手定的（window=15、k=21、deg=12/alpha=8），却得出"KRR 更强"的对比结论；`3942513879_2247501925_1` —— 把单个默认参数的基线，与在**同一份 `X_train`** 上选出来的 324 个配置的 argmax 对比，是典型的 winner's curse 比较，若不配嵌套协议，该差距不可解释；`3942513879_2247500893_1` —— SARIMA 阶数完全没搜（注释里才提"实际项目应网格搜索/信息准则选择"），却把它当作结构基准参与结论。
- **正例（带 key）**：`3942513879_2247500921_1` —— 用 Ridge，`alpha` 由时间序交叉验证选择；`3942513879_2247501029_1` —— "先大学习率找方向、再降学习率加树数"与"`n_estimators` 给大 + 早停"作为基线配置模板。
- **关联**：`P5-01`（边界 argmax）与 `P5-02`（CV 与测试差值）共同构成"选择协议是否干净"的判据。

### P4-06 · 选型理由用机制对照表，并写明不适用场景

- **类别 / 强度 / 适用模式**：`BASE` · `SHOULD` · `both`
- **机理**："因为它强"不可证伪，也无法在后续轮次被推翻；机制对照（优化信息、正则化方式、缺失值处理、抗过拟合机制、不可微结构）把选型转成可讨论的假设，并强制作者写出**在什么条件下这个选择会失效**。不适用场景是选型的另一半。
- **工程落地**：`ML_BRIEF.md` 的"模型选择"栏用一张表：`候选 | 优化信息 | 正则手段 | 缺失处理 | 抗过拟合机制 | 何时不适用 | 本项目为何选它`。至少覆盖两个候选，且"何时不适用"一列不得为空。
- **判定方式**：人工判据 —— 表存在且每个候选的"何时不适用"有具体条件（含数据规模/维度/关系形态），不接受"数据太差"这类空话。
- **违反的后果**：**不可归因** —— 选型成为偏好陈述，出问题后无法定位是选型错还是实现错。
- **语料反例（带 key）**：`3942513879_2247501959_1` —— "XGBoost 抗过拟合更强"全靠正则项的存在性论证，没有训练/验证曲线、没有早停、没有多组超参对比；`3942513879_2247501735_1` —— 清单条目的存在不等于文中给出过任何验证，引用时只能当"目录索引"不能当方法依据。
- **正例（带 key）**：`3942513879_2247501959_1` —— 原文那张 GBDT vs XGBoost 的九行对比表（核心思想 / 优化信息 / 正则化 / 剪枝 / 列采样 / 缺失值 / 训练速度 / 抗过拟合 / 工业表现）可直接作为"选型与理由"一栏的模板；`3942513879_2247500496_1` —— 目录里反复出现的"局限性 / 在什么情况下它可能不适用"类问句，应作为 `ML_BRIEF.md` 的固定栏目；`3942513879_2247502529_1` —— 明确的建模阶梯：先正则化线性基线（Elastic Net / Logistic / Cox），跑通后再考虑 XGBoost，最后才考虑深度模型，并给出理由（400 个患者、80 个左右事件，用深度学习非常容易出现训练集漂亮、换批患者马上掉）。
- **关联**：`P0-06`（不得把标题当依据）约束"理由"的来源；`P5-09`（容量与正则预算）是选型之后的下一步。

### P4-07 · 消融清单必须在同一切分与随机种子下落地

- **类别 / 强度 / 适用模式**：`BASE` · `MUST` · `both`
- **机理**：不同随机种子造成的指标波动常常大于组件之间的真实差异（同一搜索的两次训练排名相关性可以很低）。跨种子比较组件，等于在噪声上做减法；此外列了清单却不执行，会让"计划里的消融"在阅读时被当成"做过的消融"。
- **工程落地**：消融矩阵固定 `split_hash` 与 `seed` 两个字段；每档至少跑 3 个种子，报均值 ± 区间（见 `P9-03`）。清单在契约里出现即视为待执行项，执行状态逐项写进产物（`done` / `skipped + reason`）。
- **判定方式**：可机检 —— 消融结果表含 `seed` 与 `split_hash` 两列且组内取值唯一；断言每个清单项有状态字段。
- **违反的后果**：**结论无效** —— 组件差异落在噪声内却被宣布为有效；或"计划过的消融"被读成已做。
- **语料反例（带 key）**：`3942513879_2247502133_1` —— 无验证集、无多种子、无基线对照，"融合更强"没有证据支撑；`3942513879_2247501205_1` —— 只给了单折、单种子的 Accuracy=0.994，KMeans 与 GMM 只有图形对比没有量化对照；`3942513879_2247500609_1` —— 五种玫瑰图各用不同种子，图间不可比，与"同一批样本 + 同一随机种子"的对照设计形成鲜明反差。
- **正例（带 key）**：`3942513879_2247502630_1` —— 要求"在相同时间切分和随机种子下做消融，结论才站得住"（但该文只列了清单没有实现，项目契约应要求清单落地）；`3942513879_2247500661_1` —— "同一批样本 + 同一随机种子 + 只切换预处理"的 A/B 对照设计，六组图全部基于同一份数据。
- **关联**：`P4-04`（消融内容）依赖它保证可比；`P9-03`（多种子区间）提供报告格式。

## 7. P5 · 训练与调参

**本阶段的目标与出口物**：让"训练过程是否真的在收敛、搜索是否真的在端点内、超参是否有量级依据"三件事变成可读出的诊断量；出口物是训练/验证曲线 + 搜索轨迹 + 超参量级依据表。

### P5-01 · argmax 贴在搜索网格边界时必须扩界或声明不可辨识

- **类别 / 强度 / 适用模式**：`DIAG` · `MUST` · `both`
- **机理**：最优值落在搜索区间端点上，说明真实最优可能在区间之外 —— 此时报告的"最优超参"只是**网格的边界**，不是数据的最优。把边界值当结果，会让性能上界的估计系统性偏低，并让后续所有关于"模型能力"的讨论建立在未搜索的空间上。
- **工程落地**：搜索结束后对每个超参检查 `argmax` 是否位于端点；命中则二选一：(a) 向该方向扩界重跑，或 (b) 在报告中声明"该参数在搜索区间内不可辨识，最优值位于边界"。两种情况都写进结果表。
- **判定方式**：可机检 —— 断言 `argmin/argmax` 的索引不在网格首尾；或结果对象带 `boundary_hit: true` 与 `unidentifiable: <param>` 字段。
- **违反的后果**：**结论无效** —— 报告的性能上限与"最优超参"都不成立；扩界后可能推翻整段结论。
- **语料反例（带 key）**：`3942513879_2247500642_1` —— LML 最优落在 `length_scale` 的上端且仍单调上升，原文把该端点当作结果呈现；`3942513879_2247501064_1` —— 最优 CV 出现在 `γ = 1.0`，恰是搜索过的最大值。
- **关联**：`P5-02`（CV 与测试差值）共同判断搜索是否可信；`P5-07`（超参量级依据）常常直接解释边界命中的原因（量级选错导致最优被推出网格）。

### P5-02 · 必须报 CV 与测试的差值并核对选择协议

- **类别 / 强度 / 适用模式**：`DIAG` · `MUST` · `both`
- **机理**：测试分数与验证分数之间应当存在**系统性但不大的差距**（测试更难或更易都正常，差值应落在同一量级）。若测试分数**高于**最优验证候选，说明选择协议与报告协议不一致 —— 常见原因是网格行被索引操作静默丢弃、或测试集在流程中被反复看过。
- **工程落地**：结果表固定三列：`best_valid`、`test`、`gap = test − best_valid`，并写一句对 gap 的解释（预期范围、是否在噪声内）。同时记录每次读取测试集的次数。
- **判定方式**：可机检 —— 断言 `gap` 已记录；断言 `gap > 0` 时存在解释字段；断言搜索结果的候选行数等于网格全尺寸（防止 `pivot_table`/`dropna` 静默丢行）。
- **违反的后果**：**指标虚高** —— best-of-N 统计量被当成泛化估计；最严重的情况是流程里存在第二个泄漏点而未被察觉。
- **语料反例（带 key）**：`3942513879_2247501925_1` —— 用 5 折 CV 选出配置后报出的测试 AUC 比任何配置的 CV 均值高 +0.031，若选择与报告共用一套协议则不可能，且与一个被静默丢掉的 `max_depth=None` 网格行一致（`pivot_table` 丢弃 NaN 键）。
- **正例（带 key）**：`3942513879_2247502382_1` —— 配对实验设计中同数据划分、同折、同种子分别训练基线与新模型，取差值分布统计，从协议上消除了"这个 seed 数据本身容易"的混淆。
- **关联**：`P2-02`（选择只能用 train/valid）是它的前提；`P9-03`（区间而非单点）用来判断 gap 是否落在噪声内。

### P5-03 · 早停必须回滚 best state，并记录有效训练轮数

- **类别 / 强度 / 适用模式**：`DIAG` · `MUST` · `both`
- **机理**：早停的语义是"回到验证损失最低的那一刻"，实现上必须显式保存并恢复权重。"训练完再从历史里挑最好"与"触发即中断并恢复"两种写法在结果上等价，但**未恢复的版本用的是最后一轮权重**，此时模型可能已过拟合若干轮。有效训练轮数是判断"这个模型到底学了多少"的唯一线索。
- **工程落地**：维护 `best_state`（模型参数副本）与 `best_epoch`，训练结束后 `load_state_dict(best_state)`；日志中打印 `best_epoch` 与总轮数，并在报告中写明有效轮数。若有效轮数 ≤ 2，必须把它作为结论的一部分（"该组件的有效训练只有 1 轮"）。
- **判定方式**：可机检 —— 断言恢复后的权重哈希等于 `best_state` 的哈希；断言日志含 `best_epoch` 字段；断言该字段已出现在结果表中。
- **违反的后果**：**结论无效** —— 报出的模型不是早停选中的模型；深度组件可能在"其实没训练过"的状态下被宣布无贡献或有效。
- **语料反例（带 key）**：`3942513879_2247500727_1` —— 图 3 实测验证损失从 epoch 2 起单调上升、两条曲线在 epoch ≈ 1.5 交叉、早停恢复的是 epoch 1 的权重 —— 整个深度残差模型的"有效训练"只有 1 轮，图 6 上深度残差分量几乎恒为 0，即"CNN+LSTM+Transformer 三分支门控融合"是一个昂贵但没有产出的组件；`3942513879_2247501298_1` —— 训练过程按验证集 loss 取最优 epoch 的权重，是"训练完再从历史里挑最好"而非真正中断，实现上必须补回滚。
- **正例（带 key）**：`3942513879_2247500632_1` —— 训练三件套纪律：以验证集 NLL 为监视量做早停（patience=8）并保存 `best_state`；`3942513879_2247502684_1` —— 验证集 + 早停（patience=5）+ 恢复最优权重，训练/验证损失曲线作为判据。
- **关联**：`P5-05`（曲线配判据）提供判断依据；`P5-04`（收敛判定）区分"早停"与"训练不足"。

### P5-04 · 收敛判定用"最近 N 轮变化 < 阈值"，不用话术

- **类别 / 强度 / 适用模式**：`DIAG` · `MUST` · `both`
- **机理**：收敛是一个**可计算的停机条件**："最近 N 轮目标函数变化小于阈值 ε"。用"曲线整体上升，后期趋于平稳"这类描述替代，会把"第 2 步就收敛、之后 43 步是水平平台"讲成"逐步改善"，从而高估训练量并掩盖 `max_iter` 设置过大。
- **工程落地**：训练循环里写显式停机判据（`patience` 轮内变化 < `tol`）并打印实际收敛步数；报告中同时给出"收敛步数"与"y 轴是否为每样本量"，并据此决定 `max_iter`（示例：`max_iter` 可设 5 而非 50）。
- **判定方式**：可机检 —— 断言训练日志含 `converged_at_step` 与 `stop_reason` 两个字段；断言绘制的收敛曲线横轴覆盖到收敛点之后至少 2 个 `patience` 长度（否则无法看出平台）。
- **违反的后果**：**不可归因** —— 调参轮次被浪费在早已收敛的维度上；"模型还在学习"的判断错误。
- **语料反例（带 key）**：`3942513879_2247500488_1` —— 正文写"每一次循环，都会让模型更会'解释'这些数据""曲线整体上升，后期趋于平稳"，实测上升全部发生在第 1~2 步（−4.2912 → −4.2717），之后 43 步是水平平台；该篇还有一处真实错误：纵轴标签写"平均对数似然下界"，而 `lower_bound_` 是总值（未除以 N）。
- **正例（带 key）**：`3942513879_2247500488_1` —— 随机初始化多跑几次取最优（`n_init=5`）+ 协方差正则（`reg_covar=1e-5`）是 EM 类的两条标准防线。
- **关联**：`P5-05`（把判据套用到自己的图上）是它的前提；`P9-05`（过程量落盘）保证收敛步数可被复核。

### P5-05 · 训练/验证曲线必须配判据，并把判据套用到自己的图上

- **类别 / 强度 / 适用模式**：`DIAG` · `MUST` · `both`
- **机理**：曲线本身不构成结论；必须先声明判读规则（如"训练降/验证升 ⇒ 过拟合""对角线亮=近期、远处亮=长程"），再据该规则读数。这样做的价值是**可被他人检查**：判据写在图上，任何人都能核对读数是否与图一致。反之，通用预期会替代本次实测。
- **工程落地**：每张诊断图的图注写两行：第一行"判据：…"；第二行"读数：…"。读数必须具体到数值或可见结构，且给出由此得到的结论（含"本图落入判据的哪一侧"）。
- **判定方式**：可机检 —— 断言每张诊断图的标题/图注含"判据"与"读数"两段；人工复核读数的数值与图面一致（抽查 ≥ 1 张/轮）。
- **违反的后果**：**结论反转** —— 自己的图落进自己写的过拟合判据里，却得出"模型学会了"的结论。
- **语料反例（带 key）**：`3942513879_2247500971_1` —— 正文写"损失应会稳步下降，说明模型学会了把全局信息聚合起来"并给出"训练降/验证升 ⇒ 过拟合"的判据，而自己这张图恰好落进该口径（验证损失全程在涨），正文却没有据此下"本案例已过拟合"的结论 —— 语料注为"作者写下了正确判据，但没有把判据套用到自己的图上"；`3942513879_2247500289_1` —— 奖励曲线从头到尾没有上升趋势，文章没有据此下结论，反而把奖励曲线的解释写成"一般会缓慢向上"，用通用预期替代本次实测。
- **正例（带 key）**：`3942513879_2247500364_1` —— 图 4 写"train/val 同步下降 = 稳定规律"、图 6 写"对角线亮=近期、远处亮=长程"，"先把判据写在图上"这个习惯应当保留（本批多篇正是因为判据写清楚了，才能被检查出结论与图相反）。
- **关联**：`P10-05`（图上先写判据）是它在交付层的规则化；`P5-06`（无趋势即结论）是它的一个具体判据。

### P5-06 · 训练预算与任务规模必须匹配；曲线无趋势本身就是结论

- **类别 / 强度 / 适用模式**：`DIAG` · `MUST` · `both`
- **机理**：在线学习、batch=1、无优势归一化、无奖励缩放、每集被步数上限截断 —— 这些配置会让训练在统计上无法累积梯度信号，表现为指标曲线全程无趋势但仍在其初始值附近波动。这种曲线不是"还在训练"，而是**已经失败**；判据是趋势项与量级，不是末值。
- **工程落地**：契约里写死训练预算（episode 数、总步数、batch、学习率、归一化手段），并检查"总步数 vs 参数量/任务复杂度"是否同量级；对每类曲线（损失、奖励、准确率、熵）给出趋势判据与触发动作。
- **判定方式**：可机检 —— 断言损失/奖励序列的线性拟合斜率显著（或显式记录"无趋势"）；断言训练总步数 ≥ 契约下限；断言损失曲线首 epoch 不含量级异常（如 8e9 级爆炸）——命中即判不通过。
- **违反的后果**：**结论无效** —— "模型没学到东西"被读成"方法无效"或"数据噪声大"，方向性错误会被带进下一轮。
- **语料反例（带 key）**：`3942513879_2247500289_1` —— 30 个 episode、每集被 1800 步上限截断、batch=1 的在线 A2C、无 advantage 归一化、无 reward 缩放；图 2-1 的奖励曲线全程为负（−0.86 ~ −0.72）无上升趋势，熵却在单调上升到 ln 3 ≈ 1.0986（三动作均匀分布的最大熵），Critic Loss 第 10 轮后贴地到约 2e-4（价值函数退化为常数）；`3942513879_2247501612_1` —— 损失曲线首个 epoch 出现 8e9 量级的爆炸，验证曲线在该尺度下不可辨，逐步误差 ≈255（比数据量级大两个数量级）且不随步数增长。
- **关联**：`P5-04`（收敛判据）与 `P5-03`（有效轮数）共同决定"训练是否值得继续"；`P9-05`（过程量落盘）保证这些量可复核。

### P5-07 · 关键超参必须给出量级依据

- **类别 / 强度 / 适用模式**：`DIAG` · `MUST` · `both`
- **机理**：核带宽、长度尺度、GMM 协方差正则、状态噪声/观测噪声比等超参的**正确量级由数据尺度决定**，不由手感决定。取错量级时模型不会报错，而是退化：RBF 核矩阵趋近单位阵（每样本自成一体）、平滑基线逐点跟随噪声（增益接近 1）。退化后的图形恰好"看起来很干净"，因此最容易被当成成功。
- **工程落地**：对每个量级敏感超参写出确定方式与量级估算（如 `gamma='scale'` = `1/(n_features·Var(X))`；或按样本间中位距离 `γ ≈ 1/(2·median(‖x_i−x_j‖²))`），并附一次核矩阵/相似度矩阵的**量级检查**（非对角元的中位数、有效秩）。状态空间模型必须给出 q、r 的估计依据（EM 或边缘似然最大化），不得用启发式系数。
- **判定方式**：可机检 —— 断言核矩阵非对角元中位数不趋近 0（不退化）；断言超参值有对应的量级计算式记录；断言 q/r 估计方法字段非空。
- **违反的后果**：**结论无效** —— 用来解释方法的图（核矩阵热力图、相似度分布）因退化而全黑/全白，整段论证失去证据。
- **语料反例（带 key）**：`3942513879_2247500338_1` —— γ 是 RBF 核唯一的关键超参，其正确量级对标准化二维数据约为 0.5，文章取 6 和 8（大一个数量级以上），导致核矩阵所有非对角元 ≈ 0（`exp(−8×4) ≈ 1.3e−14`），直接毁掉了它用来解释核技巧的两张热力图（图 7/图 8 全黑）；`3942513879_2247500632_1` —— `q_est/r_est` 用启发式系数（×0.05、×0.5）粗估，正文自己承认"这只是演示，真实项目会更严谨"；该篇另一处：正文说"贝叶斯基线比较平滑"，而图 1 实测基线几乎逐点跟随噪声（增益接近 1），"局部水平模型"当基线时必须先验证它真的有平滑性；`3942513879_2247501420_1` —— K 只搜了 4 个点、10~35 区间无点，图 5 在 15~35 已呈平台，无法确认真正最优。
- **关联**：`P3-03`（尺度敏感性）是它的前置条件；`P5-01`（边界命中）往往是量级选错的直接征兆。

### P5-08 · 概率模型的两类不确定性必须量级可辨

- **类别 / 强度 / 适用模式**：`DIAG` · `MUST` · `both`
- **机理**：不确定性的拆分（认知型 vs 偶然型）来自方差分解：一类来自模型参数的样本间差异，一类来自观测噪声。若其中一项的实现路径被意外关闭（dropout 只作用在顶层而 RNN 内部为 0、采样次数不足），该项会恒为 0，而**求和后的总方差看起来仍然正常**。因此必须直接检查两项的量级，不能只看区间宽度。
- **工程落地**：在"最小测试集"里断言 `Var[μ]`（认知型）与 `E[σ²]`（偶然型）的量级比落在约定区间（例如不超过两个数量级）；若某一项恒为 0，必须报告"另一块未检出"，并说明是模型结构限制还是采样不足。
- **判定方式**：可机检 —— 断言两项的比值已计算并记录；断言任一项的标准差 > 0；比值超限时断言报告中存在"未检出/实现受限"的说明。
- **违反的后果**：**结论无效** —— "不确定性拆分"实际没有实现，却用大段篇幅解释各分量含义；区间宽度给出的置信语义不成立。
- **语料反例（带 key）**：`3942513879_2247500632_1` —— Epistemic 不确定性实测几乎恒为 0（图 4），与 Aleatoric 相差约两个数量级，原因很可能是 MC Dropout 的多样性不足（`nn.LSTM` 的 `dropout` 因 `num_layers=1` 被设为 0.0，dropout 只作用在最上面一层），即"不确定性建模欠拟合"，原文完全没有讨论；`3942513879_2247500599_1` —— 异方差 NLL 双头 LSTM 是最低成本的可迁移方案，但必须配套区间覆盖率实测与测试集覆盖极端工况两条约束，否则会得到"看起来有区间、其实没意义"的结果。
- **关联**：`P6-03`（校准：覆盖率 + 宽度）是它在评估侧的要求；`P8-04`（不确定性职责划分）是它在部署侧的要求。

### P5-09 · 容量与正则是同一预算的两个维度，必须联合搜索

- **类别 / 强度 / 适用模式**：`DIAG` · `SHOULD` · `both`
- **机理**：容量（深度、阶数、隐藏维度、树深）与正则强度是**耦合**的：容量上去了正则不跟上就过拟合，正则过强而容量不足则欠拟合，二选一搜索必然收敛到次优。此外"容量"不等于"参数量"—— KNN、树、核方法都可能没有多少训练参数却过拟合，容量由邻居数、深度、带宽决定。
- **工程落地**：搜索空间写成二维（或更多维）联合网格，而不是"先定容量再调正则"；`ML_BRIEF.md` 增加一栏"容量与正则预算"：预估参数量/容量上界 + 计划的正则手段 + 搜索范围。
- **判定方式**：可机检 —— 断言搜索空间包含容量维度与正则维度两个键；断言"本模型的容量由什么控制"一句已写入契约。
- **违反的后果**：**结论无效** —— 报出的最优配置只是"沿着一条任意选定的搜索路线"的最优；模型结论（"该模型不适合本任务"）可能是搜索策略的产物。
- **语料反例（带 key）**：`3942513879_2247500232_1` —— 该篇真正的病是欠拟合（深度太小）而非过拟合，原文未识别这一点（把"调参"当作提升性能的默认手段）；`3942513879_2247502221_1` —— "模型复杂度 ≠ 参数数量"，KNN、树、核方法都可能"没有训练参数却过拟合"，ML_BRIEF 应要求显式回答"本模型的容量由什么控制"；`3942513879_2247502796_1` —— 图 2 的边界只是少数几个轴对齐的竖直/水平切分拼成的粗阶梯，按正文自己给的判据该图落在"很多区域分不开"（欠拟合）一侧，正文既没承认也没说明它属于哪一类。
- **正例（带 key）**：`3942513879_2247501294_1` —— 把"容量（degree）× 正则强度（α）"当成一个二维耦合问题来搜，而不是二选一；`3942513879_2247500784_1` —— 明确的"先容量后正则"顺序："先多 knot 让它能动，再加大 alpha 把它压平"。
- **关联**：`P4-05`（预算对等）保证联合搜索的预算也分配给对照方案；`P5-01`（边界命中）是搜索空间设计不当的直接征兆。

## 8. P6 · 评估与指标

**本阶段的目标与出口物**：让指标能看见自己关心的失效模式，而不是看见"平均起来还行"；出口物是结果表（含基线行、作用域、区间、成本）+ 一份"本指标看不见什么"的声明。

### P6-01 · 指标必须能看到关心的失效模式（退化断言可机检）

- **类别 / 强度 / 适用模式**：`METRIC` · `MUST` · `both`
- **机理**：平均型指标对退化模型不敏感：全预测多数类可以有 99.8% 准确率，正类召回却是 0；AUC 低于 0.5 说明排序方向反了，但若只看准确率完全看不出来。因此每个指标集必须配一组**会失败的断言**，把"模型退化了"变成一次构建失败，而不是一段需要人去读的图。
- **工程落地**：在评估脚本末尾写退化断言并接入验收：`assert (y_pred_pos.sum() > 0)`、`assert auc >= 0.5`（AUC < 0.5 即报警）、`assert len(set(y_pred)) > 1`（分类）、`assert y_pred.std() > 0`（回归）。断言失败时脚本以非零状态退出。
- **判定方式**：可机检 —— 断言存在且全部通过；断言结果落进产物（`degeneracy_checks: passed` 列表）。
- **违反的后果**：**结论无效** —— 退化模型被当作结果报告，并在此基础上做可解释性分析（重要性、混淆矩阵）而不自知。
- **语料反例（带 key）**：`3942513879_2247500069_1` —— 标签极度不平衡下模型退化成"全预测 0"，正类召回 = 0、准确率 99.8%、混淆矩阵 `[[499,0],[1,0]]`，两套模型的 AUC 都在随机线以下（0.152 / 0.421），而文章对此毫无察觉；`3942513879_2247500875_1` —— 一个"获胜"的编码方案，其混淆矩阵 TP = 0（正类约占 4.4%），无人提及；`3942513879_2247501901_1` —— 正文预告"ModerateSampling 更稳"，而 Test AUC 是 NoSampling 0.9734 > ModerateSampling 0.9727 > AggressiveSampling 0.9726，且画特征重要性/PDP/混淆矩阵所用的 `best_model` 正是 NoSampling，核心论点未被自己的实验支持。
- **关联**：`P1-09`（one-hot 退化检查）与 `P5-06`（曲线无趋势）是同类断言在其它环节的形式；`P6-02` 提供不均衡场景下的替代指标。

### P6-02 · 不均衡必须报逐类召回/macro 指标 + 多数类基线

- **类别 / 强度 / 适用模式**：`METRIC` · `MUST` · `both`
- **机理**：总体准确率在类别占比悬殊时被多数类支配，少数类的表现几乎不影响它；macro 平均把各类等权处理，逐类召回则直接暴露"某个类完全没被识别"。两者相加，才能让"少数类塌陷"这类失效模式进入报表。
- **工程落地**：分类任务固定报：逐类 precision/recall/F1 + macro-F1 + 混淆矩阵 + 多数类基线分数。三类以上任务同时给出每类的样本数与占比。阈值相关指标附带所用阈值（见 `P6-06`）。
- **判定方式**：可机检 —— 结果表含逐类召回行与 macro 行；断言多数类基线分数已计算；断言分类任务的结果里不存在"只有 accuracy 一行"的情况。
- **违反的后果**：**指标虚高** —— 少数类完全塌陷仍可报出高准确率；报告的改进可能只发生在多数类上。
- **语料反例（带 key）**：`3942513879_2247501064_1` —— 五分类任务只报 accuracy，没有提约 22.6% 的多数类基线；`3942513879_2247501051_1` —— 三个类，恒定预测外圈即可拿到约 65.8% 准确率；`3942513879_2247502936_1` —— 更强增强让测试准确率 88.9% → 88.3% → 87.8%、少数类召回 43.8% → 31.3% → 18.8% 单调下降，正文却宣称两者都提升了。
- **关联**：`P6-01`（退化断言）是它在标签层的对应；`P6-06`（阈值绑定代价方向）决定在哪个工作点报逐类指标。

### P6-03 · 概率输出必须同时报校准曲线、区间覆盖率与区间宽度

- **类别 / 强度 / 适用模式**：`METRIC` · `MUST` · `both`
- **机理**：排序能力好不等于概率可信。校准误差与区间宽度是两个独立维度：把区间放得很窄覆盖率必然偏低，放得很宽则覆盖率达标但信息量为 0。只报其中之一，都可以通过牺牲另一者来"看起来达标"。因此覆盖率与宽度必须同表报出，并给出名义覆盖率与实际覆盖率的偏差。
- **工程落地**：概率/区间类任务固定产出：可靠性曲线（含"完美校准"参考线）、分位点的实际覆盖率（如 q=0.5/0.8/0.9）、区间平均宽度、以及 `|实际覆盖率 − 名义覆盖率|` 的最大值。验收阈值写进契约（例如偏差 ≤ 0.05）。
- **判定方式**：可机检 —— 断言覆盖率与宽度两列都存在；断言偏差最大值已计算并与契约阈值比较；断言校准曲线图例包含参考线与至少一条模型曲线（仅一条曲线时必须查明原因并如实记录）。
- **违反的后果**：**结论无效** —— "有区间"不等于"区间可信"；下游按区间做决策会系统性过度自信。
- **语料反例（带 key）**：`3942513879_2247500632_1` —— 预测区间系统性过窄（图 6：q=0.5→0.43、q=0.8→0.77；图 2：真值频繁冲出 90% 带），而正文只用一句"蓝线靠近红色虚线越近，说明校准越好"敷衍过去，没有如实承认本文的校准失败；`3942513879_2247502607_1` —— 图右的 Raw 与 Calibrated 曲线几乎重合，说明本例校准几乎无效，但正文用的是条件句"如果校准以后明显靠近对角线……"；`3942513879_2247501609_1` —— `SVC(probability=True)` 会触发内部 Platt 校准，该文自己用校准曲线发现 SVM 过度自信，说明"有概率输出" ≠ "概率对"。
- **关联**：`P5-08`（不确定性量级可辨）是它的前置；`P8-03`（校准失败告警）是它在部署侧的触发条件；`P6-12`（带宽随 horizon）是时序场景下的补充。

### P6-04 · 必须报 bias / 收缩量，而不只是误差范数

- **类别 / 强度 / 适用模式**：`METRIC` · `MUST` · `both`
- **机理**：RMSE/MAE 对"系统性偏移"与"随机噪声"不区分。收缩偏差（把振幅压向均值）会同时降低 RMSE 与峰值区间的解释力，表现为曲线更平滑、看起来更"稳"，而实际是把信息抹掉了。报 bias（平均预测减平均真值）、斜率（预测对真值的回归系数）或振幅比，才能把这种失效与噪声区分开。
- **工程落地**：回归/时序任务固定报：`bias = mean(ŷ − y)`、预测对真值的 OLS 斜率（理想为 1）、极值段（Top-5%/Bottom-5%）的平均偏差。三项与 RMSE 同表。
- **判定方式**：可机检 —— 断言结果表含 `bias` 与 `slope` 两行；断言斜率与 1 的偏差已与噪声区间比较（偏离显著时必须写入结论）。
- **违反的后果**：**结论反转** —— 收缩型模型因其平滑外观被评价为"更稳更好"，而它实际上连动态范围都没覆盖。
- **语料反例（带 key）**：`3942513879_2247500249_1` —— 橙虚线是绿实线的一条平滑滞后版本：尖峰段真值 9.6~10.15 而预测上限约 9.0、低谷段真值约 5.9 而预测约 6.6，不是零均值噪声而是系统性把振幅压缩到均值附近的收缩偏差，模型从未预测出超过 9.0 的值（合成序列脉冲幅度到 13.5）；`3942513879_2247502274_1` —— 图注写"图 5 看着贴得近"与读数不符：混合模型在 24 步上系统性低于基线约 0.7–1.5，与真值最大相差 3.0 以上；`3942513879_2247500546_1` —— 图 4 暴露严重预测压缩（真实值 −9..27，预测值被压到 2..15，真值 y>15 时预测封顶在约 13–15），正文完全没提，只贴了一段通用的"偏上=高估/偏下=低估"模板。
- **关联**：`P6-05`（峰值/Top-K）是它的极值版本；`P1-10`（峰值保持率）说明其中一部分偏差可能来自输入栅格化而非模型。

### P6-05 · 别只看 RMSE：必须报峰值与 Top-K 极值段的召回

- **类别 / 强度 / 适用模式**：`METRIC` · `MUST` · `both`
- **机理**：全局平均误差被平缓区间支配，极端段（峰值、尖峰、失效位置）的贡献被摊薄。而工程关心的问题（峰值位置、极值是否被捕捉）恰好只在极端段显现。因此必须单独报极值段的召回/命中率与峰值保持率。
- **工程落地**：固定报三组：Top-K% 极值样本的召回、极值段上的误差、以及预测分布的极值范围 vs 真值范围（比值）。在 fem 模式下同时报栅格化峰值保持率（见 `P1-10`）。
- **判定方式**：可机检 —— 断言结果表含 `topk_recall`（或等价）与 `pred_range / true_range` 两行；断言比值不在 [0.8, 1.25] 内时有解释字段。
- **违反的后果**：**结论无效** —— 模型整体误差达标但从不命中关键区段，却在平均指标上表现为"可用"。
- **语料反例（带 key）**：`3942513879_2247502927_1` —— 正文判据是"小波 LSTM 的频谱整体更低，才表示它真正学到了多尺度规律，而不只是让预测曲线变得更平滑"，实测子图 2 中小波 LSTM 的滚动 MAE 在全部时段都高于普通 LSTM（起点 ≈0.6 vs ≈0.35，终点 ≈2.45 vs ≈1.4），而它的预测曲线恰恰是更平滑的那一条；`3942513879_2247500249_1` —— 模型从未预测出超过 9.0 的值；`3942513879_2247500546_1` —— 真值 y<0 时预测值被抬到 3 附近、y>15 时封顶。
- **关联**：`P6-04`（bias/收缩）与 `P1-10`（峰值保持率）共同解释极值段失效的来源。

### P6-06 · 阈值必须绑定业务代价方向，并报移动后的混淆矩阵

- **类别 / 强度 / 适用模式**：`METRIC` · `MUST` · `both`
- **机理**：阈值是**决策变量**，不是模型属性。它的正确方向由代价结构决定：把阈值抬高只会让判定更保守（少报正类 ⇒ FN 升、FP 降），阈值降低则相反。这个方向是**数学上确定的**，因此任何"阈值移动后 FN 下降、FP 增加"式的通用表述都必须先核对本文的移动方向。
- **工程落地**：报告里每个阈值相关数字都带阈值；给出阈值扫描表（至少 5 个点）与对应的 TP/FP/FN/TN；写一句"本文阈值移动方向 → 混淆矩阵各格的实际变化"。阈值在验证集上选定后冻结。
- **判定方式**：可机检 —— 断言每个阈值相关指标行含 `threshold` 字段；断言存在扫描表；断言"阈值 − 混淆矩阵方向"的一致性检查已通过（阈值升高 ⇒ FN 不减）。
- **违反的后果**：**结论反转** —— 报告的代价权衡方向与实际相反；据此做出的业务决策方向错误。
- **语料反例（带 key）**：`3942513879_2247500302_1` —— 正文写"阈值移动后，FN（漏报）往往显著下降，但 FP（误报）会增加"，实测阈值 0.5 → 0.88 后 FP 从 486 降到 21（下降）、FN 从 28 升到 60（上升）、TP 从 52 降到 20，方向完全相反（原因是本文的 F1 最优阈值 0.88 高于 0.5，把判定推向更保守）；该篇同时被点出混淆了"改排序能力"与"改工作点"两类手段：`class_weight` / SMOTE 改变的是工作点，对 AUC/AP 没有必然后益，本文图 3、图 4 正是教科书实例（Baseline 0.742/0.363 最高，两个平衡方案反而更低），文章却写成"类权重与 SMOTE 一般优于原样训练"。
- **关联**：`P6-02`（逐类指标）需在正确工作点上报告；`P7-10`（解释量须用最终工作点）是它在可解释性上的强制延伸。

### P6-07 · 显著性判定必须给出检验名/临界值/自由度/p 值/胜率

- **类别 / 强度 / 适用模式**：`METRIC` · `MUST` · `both`
- **机理**：小差值（如 ΔAUC = 0.005）在单次运行下完全可能来自随机性。正确做法是**配对实验**：同数据划分、同折、同种子分别训练两个模型，对差值 `Δ_i = metric_new,i − metric_baseline,i` 做统计 —— 看差值的均值、置信区间是否跨 0、以及胜率。这样能消除"这个 seed 数据本身容易"的混淆，统计效率也远高于各自跑 N 次比均值。
- **工程落地**：结果表固定格式：`Baseline X ± s`、`Proposed Y ± s`、`Δ`、`95% CI [a, b]`、`Positive Runs k / N`、`p-value`、`检验名（paired t-test / Wilcoxon signed-rank / DeLong / paired bootstrap）`。N 建议 20~30。CI 跨 0 或胜率接近 50% 时必须写"未检出显著提升"。`p` 值须与临界值/自由度同列，不能只给一个数。
- **判定方式**：可机检 —— 断言上述字段全部存在；断言 CI 跨 0 时结论字段为"未检出"；断言检验的自由度或样本对数已记录。
- **违反的后果**：**结论无效** —— 把随机波动当成提升；或反向，把真实提升判成没有。二者都会误导后续资源分配。
- **语料反例（带 key）**：`3942513879_2247500130_1` —— 把 χ²=3.78（df=3，临界 7.81）这种**不显著**的结果当作显著来解读；`3942513879_2247502382_1` —— 该篇明确指出"只挑最好的 seed 汇报"是错的，并给出配对设计（同 seed 同折同划分）与四看（平均提升、95% CI、胜率、实际价值）。
- **正例（带 key）**：`3942513879_2247502382_1` —— 推荐汇报格式 `Baseline AUC 0.8121 ± 0.0062 / Proposed 0.8168 ± 0.0059 / ΔAUC +0.0047 / 95% CI [+0.0031, +0.0060] / Positive Runs 27 / 30 / p-value < 0.01`，并给出"30 次里 17 胜 13 负、CI [-0.003,+0.012] 跨 0 ⇒ 不可信"的反例对照。
- **关联**：`P9-03`（多种子区间）是它的执行前提；`P6-13`（显著 ≠ 有价值）是它的下一步。

### P6-08 · 指标必须落文，不能只 print

- **类别 / 强度 / 适用模式**：`METRIC` · `MUST` · `both`
- **机理**：`print` 的输出随会话消失，无法被评审、无法被下一轮引用、也无法与新结果对比。只存在于 stdout 的数值在流程上等价于"没有测过"，但阅读者会默认它测过 —— 这比缺失更危险。
- **工程落地**：所有评估数值写进结构化文件（CSV/JSON）并同时出现在报告正文；报告中每个数字带三要素：指标名、作用域、来源（脚本名 + 产物文件）。
- **判定方式**：可机检 —— 断言结果文件存在且非空；断言报告正文里出现的每个关键指标都能在结果文件中找到同名条目。
- **违反的后果**：**不可复现 + 无法归因** —— 后续轮次只能重新跑；跨文章的数值比较建立在不存在的数字上。
- **语料反例（带 key）**：`3942513879_2247500115_1` —— 测试集 MAE/RMSE/MAPE 的具体数值正文完全没有（只有 `print`），也无法从图上读到；`3942513879_2247501874_1` —— 只报指标名不报指标值，正文从头到尾没有给出 RMSE/MAE/R² 的任何数字，使"随机森林对复杂非线性学得不错"这一结论无据可查；`3942513879_2247500278_1` —— 四处 `print` 的输出均未出现在正文，图 5 里的 RMSE 数值是从图上目测的。
- **正例（带 key）**：`3942513879_2247501156_1` —— 把"基线 + 强模型"成对跑并同时报告 train/test 的 MSE/MAE/R²。
- **关联**：`P0-04`（三件套）要求同一个数字带作用域；`P10-01`（断言可指认）是它在图侧的对应。

### P6-09 · 每个指标必须声明其有效前提

- **类别 / 强度 / 适用模式**：`METRIC` · `MUST` · `both`
- **机理**：指标有定义域：MAPE 只适用于严格为正且远离零的目标（分母趋零时爆炸）；准确率要求类别大致平衡；AUC 需要两个类都有样本。越过定义域使用，指标给出的不是"差的估计"而是**无意义的数**，且不会报错。
- **工程落地**：在 `ML_BRIEF.md` 的指标表里为每个指标加一列"有效前提"，并在评估脚本中对前提写断言（如 `assert (y_true > eps).all()` for MAPE）。
- **判定方式**：可机检 —— 断言指标表中每个指标行的"有效前提"非空；断言对应的前提断言存在并通过。
- **违反的后果**：**结论无效** —— 一个天文数字或一个常数被写进结论，并成为后续比较的基准。
- **语料反例（带 key）**：`3942513879_2247500115_1` —— MAPE 在**标准化后的目标**上计算（该序列跨越 0），分母写的是 `trues + 1e-8`，真值接近 0 时 MAPE 会爆炸到天文数字 ⇒ 该指标在本任务上不可用；`3942513879_2247500204_1` —— 同一指标在另一任务上（y≈20~60 远离零）则可用，说明"可用性取决于任务"而非指标本身。
- **关联**：`P6-11`（不可横比）是它在多任务场景的延伸；`P0-04`（作用域）与它一起构成指标的完整定义。

### P6-10 · 多个方案给出"恰好相同"的指标必须复核

- **类别 / 强度 / 适用模式**：`METRIC` · `MUST` · `both`
- **机理**：本质不同的变换/模型给出四位小数完全一致的结果，在统计上几乎不可能发生。它通常意味着：某个环节把差异抹掉了（例如数据在该尺度下不可分）、两者的实现实际上等价、或存在未被察觉的 bug。这种"过于整齐"的一致是**强信号**，不能当作"方法都差不多"直接放过。
- **工程落地**：对结果表做一次去重检查：任意两行的全部指标完全相同 ⇒ 触发复核。复核动作：打印两者变换后数据的若干统计量（均值、标准差、分位数、两两相关）并对比。
- **判定方式**：可机检 —— 断言结果表中不存在"全指标列完全相同"的两行（除非已标记 `verified_equivalent: true` 并附统计量对照）。
- **违反的后果**：**不可归因** —— 三条本应不同的路线被当成同一条，后续所有关于"该用哪个预处理"的讨论都失去对象。
- **语料反例（带 key）**：`3942513879_2247500770_1` —— `Robust` 与 `PowerYJ`/`QuantileN` 给出完全相同的四位小数指标（KNN 都是 0.825/0.815；Logistic 都是 0.855/0.850），而线性稳健缩放、幂变换、分位数映射是三个本质不同的变换。
- **关联**：`P3-04`（预处理收益必须实测）是它的触发场景；`P4-04`（消融）常常产生这类"完全同分"的行。

### P6-11 · 不同测试集/不同标签体系上的指标不可横比

- **类别 / 强度 / 适用模式**：`METRIC` · `MUST` · `both`
- **机理**：指标是"在某个集合上定义的一个函数"。换集合（清洗后删掉了最难的样本、换了工况子集）或换标签体系（阈值规则不同、标注机制不同），函数值的变化里至少混入了"考题变了"这一项。此时两个数之差不可分解，不能说成"方法更稳"。
- **工程落地**：任何清洗/筛选/换标签前后对比，必须报两组的**样本数与目标分布**，并在**同一份未参与清洗的留出集**上另行比较。多任务/多章节的指标表之间加一行"标签体系：A / B（不可横比）"。
- **判定方式**：可机检 —— 断言对比表含 `n_samples` 与目标分位数两列；断言两组样本数不同时存在"分布差异"说明字段。
- **违反的后果**：**结论无效** —— "预处理/清洗带来提升"可能完全是考题变简单；这个错误会被写进总结并被下一轮继承。
- **语料反例（带 key）**：`3942513879_2247501038_1` —— 图 5 横轴到 3.5e7、图 6 横轴只到 3.6e6，两组的 R²/MAE 是在**不同测试集**上算的；清洗把最难的极端目标从测试集里一并删掉了，于是"清洗后指标更好"同时包含"模型更稳"与"考题变简单"两个原因，文章却据此宣称确认了异常值处理的提升；`3942513879_2247501933_1` —— 该篇第三章（硬分类 + F1）与第四章（概率图 + 不确定分析）标签生成机制不同，跨章的指标数值不可横比。
- **关联**：`P0-04`（三件套）是它的通用形式；`P4-02`（逐项对齐）要求对照用同一测试集。

### P6-12 · 外推区间带宽必须随 horizon 单调不减

- **类别 / 强度 / 适用模式**：`METRIC` · `MUST` · `both`
- **机理**：多步预测的误差按步累积（自回归滚筒更甚），因此 1 步与 15 步的不确定性不可能相同。恒定带宽意味着区间是用一个**与 horizon 无关**的量估出来的，它在外推段不构成对不确定性的陈述；更糟的是，它会掩盖"远处误差已经失控"这一事实。
- **工程落地**：误差与区间都按 horizon 分组报告（`h=1, 2, ..., H`）；绘制 `误差/horizon` 与 `带宽/horizon` 两条曲线；断言带宽序列单调不减（允许小波动，但趋势项必须 ≥ 0）。
- **判定方式**：可机检 —— 断言带宽序列的分组数 = horizon 数；断言单调性检查已执行并记录结果；断言相对收益随 horizon 的变化已报告（若有在线修正/融合组件）。
- **违反的后果**：**结论无效** —— 长 horizon 的区间宽度被低估，按区间做计划（安全裕度、库存、检修）会系统性不足。
- **语料反例（带 key）**：`3942513879_2247500784_1` —— `resid_std_full = resid_std.reindex(df.index).ffill().bfill()` 把训练段的滚动标准差一路前向填充到测试段，带宽不随预测步长增长（图 5 实测约 ±5–8 恒定），违反"多步外推误差应随 horizon 累积"的常识；`3942513879_2247502947_1` —— 修正收益随提前期衰减（相对降幅从 h=1 的 ≈63% 降到 h=15 的 ≈48%），修正后的绝对误差增长约 56% 而基线只增长约 10%，正文没有指出"相对收益会随提前期收缩"。
- **关联**：`P6-03`（覆盖率 + 宽度）是它在概率校准上的对应；`P2-06`（延拓方式）是它的成因来源。

## 9. P7 · 可解释性

**本阶段的目标与出口物**：把"模型依据什么"变成可核对的量，并明确它的**边界**（重要性 ≠ 因果、注意力 ≠ 决策依据）；出口物是可解释性产物清单（图 + 该图支撑的结论 + 判据）+ 一张"解释量的计算口径"表。

### P7-01 · 重要性必须声明 importance_type 与计算口径

- **类别 / 强度 / 适用模式**：`DIAG` · `MUST` · `both`
- **机理**：同一份特征重要性可以有多种互不等价的定义（分裂次数 weight、增益 gain、覆盖数 cover；以及置换重要性、SHAP 值）。这些量的排序可以不同，且含义完全不同。不声明口径，读者会按自己习惯的那个定义去读，结论随之漂移。
- **工程落地**：`ML_BRIEF.md` 的"可解释性"栏为每个重要性图写：`计算方式（importance_type / permutation / SHAP）| 数据集（train/valid）| 工作点（阈值）| 重复次数`。图上标题直接写这几个字段。
- **判定方式**：可机检 —— 断言重要性产物元数据含 `importance_type` 与非空的数据集字段；断言该图未使用 test 集（与 `P7-10` 联动）。
- **违反的后果**：**结论反转** —— 换一个 `importance_type` 可能换出一组完全不同的"关键特征"，据此做的特征取舍方向错误。
- **语料反例（带 key）**：`3942513879_2247501959_1` —— 不声明 `importance_type`：`xgb.feature_importances_` 的含义（weight/gain/cover）随版本变化，用来做"哪些特征重要"的结论时必须声明。
- **关联**：`P7-02`（重要性不得当因果）是它的边界声明；`P3-06`（降维归因）是同一纪律在压缩步骤上的应用。

### P7-02 · 重要性/注意力不得当因果，须附稳定性与忠实性检查

- **类别 / 强度 / 适用模式**：`DIAG` · `MUST` · `both`
- **机理**：重要性反映的是"在当前模型与当前数据上，扰动该量会改变多少输出"，它既不含干预语义，也不保证跨初始化稳定。注意力权重更是只描述信息路由，不描述决策依据。把它们写成因果或机制结论，等于把模型内部的算术关系冒充为世界的因果关系。
- **工程落地**：可解释性产物必须至少用**两种互不相同**的手段交叉验证（如跨层注意力 / 注意力熵 / 头相似度 / 梯度×输入 / 遮挡实验 / 置换重要性稳定性），并给一句稳定性陈述（多次运行下的排序相关系数或 Top-k 重合率）。措辞上统一写"模型主要依据 X"，不写"X 导致 Y"。
- **判定方式**：可机检 —— 断言解释产物清单含 ≥ 2 类方法；断言稳定性量（排序相关 / Top-k 重合）已记录；断言结论文本中"因果/导致"类词未出现（或仅出现在明确的否定句中）。
- **违反的后果**：**结论无效** —— 机制结论无据；据此做的干预（去特征、加约束）可能朝反方向。
- **语料反例（带 key）**：`3942513879_2247501815_1` 的反面被明确写出："注意力 ≠ 因果"，并要求同时看跨层注意力、Rollout、注意力熵、头相似度、梯度×注意力、遮挡实验；`3942513879_2247502513_1` —— 图 2 右的重要性显示模型 79% 集中在 `y_lag1`+`y_lag2`，该事实被用于反驳标题主张（这是一个正用），但如果把它读成"滞后项导致结果"就越界了；`3942513879_2247500364_1` —— 正文"注意力机制…告诉模型该更关注哪几个时间片、哪几个传感器"把两个独立模块说成了一个联合决策。
- **正例（带 key）**：`3942513879_2247502838_1` —— 邻接矩阵的用途分离（原始距离权重用于画图 / 行归一化用于数据扩散 / 对称归一化用于 GCN 三份分开），避免"把 GCN 归一化权重误称为实际距离关联强度"。
- **关联**：`P7-03`（注意力均匀基线）是它的一个具体判据；`P8-04`（修正对象声明）是它在部署决策上的同一条纪律。

### P7-03 · 注意力热图必须标注均匀基线 1/L

- **类别 / 强度 / 适用模式**：`DIAG` · `MUST` · `both`
- **机理**：注意力权重是 softmax 输出，天然被约束在区间内且求和为 1。色标把最大值映射到最亮，因此**即使权重全部接近均匀值，热图也会呈现出强烈的明暗反差**。不标基线，读者会把"色标对比度"读成"模型找到了重点"。判据是：最大权重与 1/L 的相对偏离是否超过噪声量级。
- **工程落地**：热图标题或图注写"均匀基线 = 1/L（L = 被注意力长度/节点数）"，并在同图或附表给出 `max(w) / (1/L)` 与 `min(w) / (1/L)`；只有相对偏离显著时才写"模型有选择性聚焦"，否则写"未观察到聚焦"。
- **判定方式**：可机检 —— 断言热图元数据含 `uniform_baseline` 字段；断言 `max(w)·L` 与 1 的偏离已计算并与噪声带比较；断言结论字段在未显著时取值为"未观察到聚焦"。
- **违反的后果**：**结论无效** —— 把色标反差当成机制发现；据此写的"模型关注了哪些时段/节点"全部不成立。
- **语料反例（带 key）**：`3942513879_2247500364_1` —— 节点注意力 30 个权重全部在 0.0317~0.0357 之间，而均匀值 1/30 = 0.0333；最大最小只差约 12%、相对均匀值只差 ±7%，即模型认为 30 个节点同等重要 —— 它没有识别出任何"枢纽"，图上之所以看起来反差强烈是因为色标把极小差异放大了；同一篇的时间注意力按行恒定（每行颜色完全相同，亮度只随列变化），既没有对角线结构也没有远距离亮点，注意力退化成固定权重的位置衰减；`3942513879_2247501195_1` —— 注意力热力图是本文唯一的模型侧解释手段，但实测权重近乎均匀（0.032–0.038），按作者自己的标准就是"没学到明确重点"，说明"画了注意力图" ≠ "得到了解释"；`3942513879_2247500632_1` —— 注意力在 4/5 样本上退化为均匀，原文完全没有提及，反而给出"关注周周期段、日周期段、突变点附近"的解读，属过度解读（只有第 0 行支持选择性注意力）。
- **关联**：`P7-06`（抽样规则）保证被平均的样本不是被挑出来的；`P10-03`（色标范围）要求把基线与范围一起写出。

### P7-04 · 高维边界/曲面必须用二维切片呈现并声明近似

- **类别 / 强度 / 适用模式**：`DIAG` · `MUST` · `both`
- **机理**：高维决策边界无法直接可视，投影到二维后会失真：可能丢弃判别方向、可能因为坐标压缩而放大锯齿。展示本身没问题，问题在于**不声明** —— 读者会把投影图当作真实边界，据此判断"模型学到了复杂结构"。
- **工程落地**：所有降维/投影图中写明范式："背景色块是模型在 X 维子空间上的分区（可视化近似），真实模型在 D 维空间决策，边界可能不同"。若用重训练的简化模型画边界，标题必须写明该模型的超参（与主模型的差异）。
- **判定方式**：可机检 —— 断言投影类图注含"近似"字样；断言图的标题里出现的模型超参与结果表中该模型一致（与 `P10-02` 联动）。
- **违反的后果**：**结论无效** —— 用低维图证明高维能力；或反过来用低维图的锯齿否定一个在高维正常工作的模型。
- **语料反例（带 key）**：`3942513879_2247502029_1` —— 该篇没有基线对照，"两刀竖切还宣称拟合了非线性结构"；`3942513879_2247502796_1` —— 边界只是少数几个轴对齐的竖直/水平切分拼成的粗阶梯，并未贴合 make_moons 的双新月弯曲结构，按正文自己给的判据该图落在"很多区域分不开"一侧。
- **正例（带 key）**：`3942513879_2247501988_1` —— 正文对图 3 写明"背景色块是 KMeans 在二维 PCA 空间上的分区（可视化近似）……虽然真实聚类发生在 5 维空间"，这个声明本身是好习惯；`3942513879_2247500687_1` —— 用 `decision_function` 画 `levels=[-1, 0, +1]` 三条等高线并标出 `svc.support_`，把"最大间隔"与"只看支持向量"变成可核对的几何证据。
- **关联**：`P10-02`（图上模型 = 报告模型）是它的强制检查项；`P7-08`（中间张量语义）保证投影用的数据与训练一致。

### P7-05 · 分布漂移用批次判别器检查，并先剥离可直接识别的特征

- **类别 / 强度 / 适用模式**：`DIAG` · `MUST` · `both`
- **机理**：单看每个特征的边缘分布，无法发现"所有单参数都没变、但参数之间的关系变了"这种联合分布漂移。训练一个分类器去区分"历史批次 vs 最新批次"，若 AUC 显著高于 0.5，说明两者可区分 ⇒ 联合分布已变。但若判别器能直接读到批次号、时间戳、机台编号，AUC 会虚高，得到的是循环论证。
- **工程落地**：判别器输入**排除**批次号/时间戳/编号等可直接识别字段；用交叉验证 AUC 作为漂移指标，并配 SHAP/重要性看是哪些特征在驱动可区分性；把"漂移特征名单 + AUC"写进产物。
- **判定方式**：可机检 —— 断言判别器特征列表与"可识别字段黑名单"的交集为空；断言漂移 AUC 已记录并与 0.5 的偏离一起报告。
- **违反的后果**：**结论无效** —— 要么漏报真实漂移（只看边缘分布），要么虚报漂移（把编号当信号），两者都让上线判断失去依据。
- **语料反例（带 key）**：`3942513879_2247502712_1` —— 批次判别器（历史=0 / 最新=1，LightGBM + CV AUC + SHAP）是检测"联合分布变化（单参数都不变但关系变了）"的廉价手段，同时必须剔除批次号/时间戳/机台编号等可直接识别的特征，否则得到虚假高 AUC；`3942513879_2247500704_1` —— 训练用的是某几个工况、部署时是新工况："分布已经变了，模型效果就可能掉很多"。
- **关联**：`P0-01`（适用域声明）与 `P8-02`（上线范围）在监控阶段的落地手段；`P7-01`（重要性口径）是它的配套报告项。

### P7-06 · 解释图必须写明取权重/取样本的时刻与抽样规则

- **类别 / 强度 / 适用模式**：`DIAG` · `MUST` · `both`
- **机理**：注意力和中间表征随训练进程剧烈变化：随机初始化附近、训练中期、收敛后的分布完全不同。同样，挑"预测正确且某类"的样本展示，会把偶然对齐说成学会了。两种做法都是**选择性展示**，且从图上无法被发现。
- **工程落地**：说明性图件必须记录：`取权重的时刻（epoch/step）`、`抽样规则（随机种子 / 全样本平均 / 分层抽样）`、`样本量`。禁止"挑样本"；正样本/负样本/预测错误样本应**分别求平均再比较**。
- **判定方式**：可机检 —— 断言注意力类产物的元数据含 `checkpoint`（epoch/step）与 `sampling` 两个字段；断言抽样规则字段不是"best" 或"correct_only"。
- **违反的后果**：**结论无效** —— 用初始化附近的噪声或精心挑出的样本证明模型学到了东西。
- **语料反例（带 key）**：`3942513879_2247500971_1` —— 注意力热力图取自随机初始化附近（训练第一个 batch），却被当作"多头＝多视角"的证据（图注实际上承认了"训练初期或特定分布也可能让某些头强调局部模式"）；`3942513879_2247501773_1` —— 注意力热力图只挑"预测正确且 label=1"的样本展示（`plot_attention_heatmap` 里的 break 逻辑），容易把"个别样本凑巧对齐"说成"模型学会了对齐"。
- **正例（带 key）**：`3942513879_2247501815_1` —— 不要只分析一个样本：正样本/负样本/预测错误样本分别求平均注意力再比较（第 07 节第 1 条）。
- **关联**：`P7-03`（均匀基线）需要抽样规则先成立才有意义；`P10-02`（图上模型 = 报告模型）是同一条"图必须对应到具体对象"的纪律。

### P7-07 · 可解释性产物必须在契约阶段声明并预留接口

- **类别 / 强度 / 适用模式**：`DIAG` · `SHOULD` · `both`
- **机理**：把解释当成事后补丁，会导致训练循环里没有保存必要的中间量（注意力权重、隐状态），只能重新训练或退而求其次地讲机制。把接口写进契约，成本通常只是几行（返回权重、缓存张量），却决定了这一轮能不能交付解释证据。
- **工程落地**：`ML_BRIEF.md` 的"可解释性"栏列出本轮要交付的图与量（注意力图、嵌入降维、系数表、载荷图、误差分层诊断），并为每一项写明取数接口（模型属性名 / 回调 / 保存路径）。
- **判定方式**：可机检 —— 断言契约里列出的每个解释产物都在产物目录中存在对应文件；断言模型属性/缓存张量名在契约与代码中一致。
- **违反的后果**：**不可归因** —— 训练完成后拿不到解释证据，只能重训或用机制论述代替实测。
- **语料反例（带 key）**：`3942513879_2247501302_1` —— 11 张技术配图（多项式欠/过拟合、Ridge/Lasso 系数路径、RF vs AdaBoost 边界、回归树结构、SVM 决策函数、ICA vs PCA、Bisecting K-Means、贝叶斯 Ridge 初值敏感性）正文一句解释都没有，读者拿不到图里的任何结论。
- **正例（带 key）**：`3942513879_2247501612_1` —— `need_weights=True, average_attn_weights=False` + 缓存 `last_*_attn`，让"训练完能画出注意力图"成为设计期就预留的能力，而不是事后补丁；`3942513879_2247500364_1` —— `need_weights=True` 缓存注意力权重 + 从模型属性取回画图的实现方式很轻量，值得抄（比 hook 简单）；`3942513879_2247501494_1` —— 注意力权重热力图实现成本只有三行（返回 alpha + sns.heatmap）。
- **关联**：`P0-03`（契约先行）在可解释性上的具体化；`P7-08`（张量语义）是接口的规格说明。

### P7-08 · 解释用中间张量的形状与语义必须写死

- **类别 / 强度 / 适用模式**：`DIAG` · `SHOULD` · `both`
- **机理**：注意力与中间表征天然是高维张量，形状里的每一维含义（批量、头、层、时间、节点）在实现中经常被隐式约定。一旦某个算子按错误的维求平均，得到的解释图在数值上完全合理却对应另一个对象 —— 这类错误不报错，只让结论失真。
- **工程落地**：契约里写死解释中间张量的形状与语义（如 `[L, B, H, T, T]`）以及所有后处理算子（平均头、取层、累积）作用的维；邻接/图结构类量明确区分不同归一化版本各自的用途。
- **判定方式**：可机检 —— 断言解释张量的 `shape` 与契约一致；断言后处理函数里每个 `mean/axis` 参数的维度名与语义表一致。
- **违反的后果**：**结论反转** —— 例如把"某几个节点"写成"全部节点平均"，会把一个没有结构的图讲成有结构。
- **语料反例（带 key）**：`3942513879_2247500364_1` —— 代码注释与实现不一致（注释说"前几个节点"，代码是 `mean(axis=0)` 全部节点），使"注意力确实退化为查询无关"与"对 30 个节点求平均后抹平了差异"两种解释无法区分，**两种解释都不支持正文的结论**。
- **正例（带 key）**：`3942513879_2247501815_1` —— 注意力张量的规范形状 `[L,B,H,T,T]` 一次返回，所有可解释性指标都在这个张量上做后处理（平均头、取层、累积），并明确"注意力 ≠ 因果"；`3942513879_2247501815_1` —— Attention Rollout 必须把单位矩阵加进去（残差=自己传给自己），否则跨层传播结果不可信；`3942513879_2247502838_1` —— 邻接矩阵三份归一化各自用途分离并在图注与代码注释中说明用的是哪一份。
- **关联**：`P7-07`（接口预留）提供对象；`P9-07`（死代码/注释与实现不一致）是同一类工程债。

### P7-09 · 线性模型与线性基必须给系数表或分量幅度图

- **类别 / 强度 / 适用模式**：`DIAG` · `MUST` · `both`
- **机理**：线性模型的系数直接给出可解释的效应方向与量级；线性基（傅里叶、多项式、B 样条）上的系数可以反解成物理量（如谐波幅度、分量曲线）。放弃这些输出，等于主动丢掉成本最低、最可信的解释证据，而去依赖更不确定的事后归因方法。
- **工程落地**：线性/广义线性模型必须输出系数表（含符号与置信区间）；线性基模型必须输出"分量拆解图"（各基函数系数乘回特征后的曲线）。合成数据 + 线性模型的场景下，额外做一次"系数 vs 真值权重"的对账。
- **判定方式**：可机检 —— 断言产物含系数表文件且列非空；断言线性基模型的每类基函数有一张分量曲线图；断言合成数据场景下存在系数与真值的对照表。
- **违反的后果**：**不可归因** —— 明明可以精确定位的问题被降级成"重要性大致如此"，且失去了验证编码/特征是否忠实传递信号的机会。
- **语料反例（带 key）**：`3942513879_2247500038_1` —— 逻辑回归系数是天然可解释的，但全文没有输出、没有解读任何系数；`3942513879_2247500704_1` —— `LogisticRegression` 的系数从未被解读（线性模型的系数是最直接的可解释性证据，本文完全没用）；`3942513879_2247500799_1` —— One-Hot 的系数直接对应每个城市的 log-odds 增量，而 `w_city`（7 个 +0.15、7 个 −0.12、其余 0）是已知真值，本是一个能直接验算"编码是否忠实地传递了信号"的完美机会，本文完全没有利用。
- **正例（带 key）**：`3942513879_2247500727_1` —— 用 Ridge 系数反解谐波幅度 `sqrt(a_k²+b_k²)`，把黑箱回归系数翻译成可读的物理量；`3942513879_2247500784_1` —— 用系数切片把季节分量拆开可视化（`coef_week` / `coef_year` 分别乘特征），把"一个 Ridge 拟合出的 16 个系数"翻译成两条可单独查看、可单独解释的季节曲线。
- **关联**：`P3-06`（载荷归因）是它在降维上的同型要求；`P7-02`（不得当因果）同样适用于系数解读。

### P7-10 · 解释量必须在最终上线工作点、且在未用于调参的数据上计算

- **类别 / 强度 / 适用模式**：`DIAG` · `MUST` · `both`
- **机理**：大多数解释量（置换重要性、部分依赖、混淆矩阵、逐类指标）都依赖决策阈值与所用数据集。若解释用的是与上线不同的阈值，或在已被用于选阈值的同一批数据上计算，则解释的对象不是上线模型 —— 它描述的是一个从不存在的配置。
- **工程落地**：解释产物的元数据写清 `threshold` 与 `dataset`（train/valid/test 及其用途标记）；断言解释用的数据集未参与阈值或超参选择（若不得不用，必须显式声明污染并附敏感性检查）。
- **判定方式**：可机检 —— 断言解释图元数据含 `threshold` 字段且等于上线阈值；断言 `dataset` 不在"已用于选择"的集合里（或该污染已声明）。
- **违反的后果**：**结论无效** —— 解释与上线口径不一致；据此做的特征取舍对上线模型不成立。
- **语料反例（带 key）**：`3942513879_2247500302_1` —— Permutation importance 在固定阈值 0.5 下计算，而文章自己论证 0.5 不是正确阈值（口径自相矛盾），而且它用的是测试集（该集合已用于选阈值）；`3942513879_2247501298_1` —— 置信区间用测试集真值残差的 std 计算（`res_std = (y_test - y_hat).std()`），属于用测试集构造上线口径，隐含乐观偏差。
- **关联**：`P2-02`（选择只能用 train/valid）是它的前提；`P6-06`（阈值绑定代价方向）提供上线的正确工作点；`P7-01`（重要性口径）要求把 `dataset` 一并写出。

## 10. P8 · 上线口径与监控

**本阶段的目标与出口物**：把"离线评估的那套参数，上线后是否还是同一套"变成可核对的事实；出口物是冻结的预处理器/模型产物 + 适用域与漂移监控口径 + 校准失效告警阈值。

### P8-01 · 上线必须复用训练时冻结的预处理器参数

- **类别 / 强度 / 适用模式**：`SCOPE` · `MUST` · `both`
- **机理**：推理期的预处理器必须与训练期**数值完全相同**（同一份均值/方差/编码表/主成分）。在推理侧重新拟合，等于用推理数据的统计量变换推理数据 —— 输出尺度与训练时的不同，且随输入批次变化；更隐蔽的是逆变换写错，把已经未缩放的预测又乘又加，产生系统性偏移。
- **工程落地**：冻结的 Pipeline 落盘（见 `P3-01`），推理脚本只允许加载；所有逆变换（`y = ŷ·σ + μ`）必须成对出现并有断言 `abs(mean(inverse_scale(model_scale(y))) − mean(y)) < tol`。保存预处理器参数（均值/方差）并在产物中列出。
- **判定方式**：可机检 —— 断言推理脚本没有 `fit` 调用；断言存在逆变换往返测试；断言部署产物里含预处理器参数文件。
- **违反的后果**：**上线失效** —— 离线指标与线上表现断崖式不一致；系统性偏移还会被误判为"数据漂移"。
- **语料反例（带 key）**：`3942513879_2247500676_1` —— 逆标准化代码保留但实际未生效（`y_pred = y_pred_s * y_std + y_mean` 把已经未缩放的预测又乘又加），代码注释承认"只对 X 做了标准化，对 Y 没有直接缩放"，是死代码；语料注为"这很可能是系统性偏移的来源"；`3942513879_2247501018_1` —— 该篇 `StandardScaler` 对整个 X 拟合（无划分故无泄漏），但迁移到有划分的项目时必须只在训练集 fit，且上线复用同一份参数。
- **正例（带 key）**：`3942513879_2247500348_1` —— §04 第 ⑥ 条"在线推理必须复用同一个 scaler（保存均值/方差）"、第 ⑦ 条"不要标准化标签"（回归里 y 是否缩放要看损失函数，会改变误差的物理意义）；语料注出 ⑦ 对应"对网格标签做标准化会改变误差的物理含义，必须显式记录反变换"。
- **关联**：`P3-01`（Pipeline 落盘）是它的实现；`P2-04`（训练/推理同分布口径）是它的原理。

### P8-02 · 必须声明适用工况范围与漂移后的失效方向

- **类别 / 强度 / 适用模式**：`SCOPE` · `MUST` · `both`
- **机理**：上线环境与训练环境必然有差异，关键是**差异能否被检测**以及**超界后如何动作**。只写"效果可能下降"没有操作含义；写清监控量、阈值与超界动作（拒绝预测 / 降级到基线 / 触发重训），才是可执行的上线口径。
- **工程落地**：复述 `P0-01` 的适用域，并补一张监控表：`监控量 | 计算方式 | 训练分布基线 | 警戒阈值 | 超界动作`。至少覆盖：输入通道的边缘分布、关键派生特征、预测分布、以及漂移判别器 AUC（见 `P7-05`）。
- **判定方式**：可机检 —— 断言监控表存在且每行五列非空；断言"超界动作"字段不是"观察/注意"这类无动作词。
- **违反的后果**：**上线失效不可见** —— 模型在新工况上静默退化，直到业务指标出问题才被发现，且此时无法判断是数据问题还是模型问题。
- **语料反例（带 key）**：`3942513879_2247500704_1` —— 该篇的"分布漂移"一条对 FEM 尤其关键：训练用的是某几个工况、部署时是新工况，正是本文所说的"分布已经变了，模型效果就可能掉很多"，应在契约里显式声明适用工况范围；`3942513879_2247500642_1` —— 域外预测均值与真值分离达 4 个单位、图 4 的 2D 等高线在数据域外出现"牛眼"伪影，全部未被承认；`3942513879_2247500587_1` —— "外推不友好"必须写清。
- **关联**：`P0-01`（适用域）是它的输入；`P8-03`（校准告警）是它的一行具体阈值；`P7-05`（漂移判别器）是它的检测手段。

### P8-03 · 校准失败必须告警：窄区间 + 大误差同时出现

- **类别 / 强度 / 适用模式**：`SCOPE` · `MUST` · `both`
- **机理**：区间过窄（覆盖不足）与大误差同时出现，说明模型**既不准也不谦虚** —— 这比"误差大但区间宽"危险得多，因为下游会按区间做计划。二者必须联合判定：单独看覆盖率会漏掉"区间很宽所以覆盖率高"的无力情形，单独看宽度会漏掉"窄而错"的情形。
- **工程落地**：设置联合告警：`|实际覆盖率 − 名义覆盖率| > τ_cov` 且 `MAE > τ_err` 同时成立即告警；告警时必须输出分位点偏差明细（如"q=0.5→0.43、q=0.8→0.77"）并写"本轮校准失败"，不得用条件句敷衍。
- **判定方式**：可机检 —— 断言告警条件已实现为代码；断言触发时产物中出现 `calibration_failed: true` 与分位点明细。
- **违反的后果**：**上线失效** —— 系统在过度自信的状态下给出决策区间；风险被系统性低估。
- **语料反例（带 key）**：`3942513879_2247500632_1` —— 预测区间系统性过窄（图 6：q=0.5→0.43、q=0.8→0.77；图 2：真值频繁冲出 90% 带），正文只用一句"蓝线靠近红色虚线越近，说明校准越好"敷衍过去，没有如实承认本文的校准失败；`3942513879_2247502607_1` —— 图右的 Raw 与 Calibrated 曲线几乎重合，说明本例校准几乎无效，但正文用的是条件句，没有承认图上没有改善。
- **关联**：`P6-03`（覆盖率 + 宽度必须同看）是它的判据来源；`P5-08`（不确定性量级）是它的成因检查。

### P8-04 · 在线修正必须说清修正对象与不确定性的职责划分

- **类别 / 强度 / 适用模式**：`SCOPE` · `MUST` · `both`
- **机理**："修正预测"可以是修正结构状态、修正系统性偏差、或两者混合，三者的可建模性与收益完全不同：只有当偏差**本身具有可建模的时间相关性**时，动态偏差修正才可能带来收益。同时，求解器离散误差、代理模型误差、标签噪声三类不确定性若混在一个协方差里，上线口径会重复计算不确定性（区间偏大）或漏算（区间偏小）。
- **工程落地**：在线修正模块必须回答两问并写入契约：①修正对象是结构状态还是预测偏差（并给出"偏差具有时间相关性"的证据，如残差 ACF）；②三类不确定性的计算职责分别归谁、是否重复计入。修正收益必须按提前期分档报告（见 `P6-12`）。
- **判定方式**：人工判据（可辅以机检）—— 契约里两个问句各有明确答案；断言残差 ACF 图存在且已用于判断偏差可建模性；断言收益表按 horizon 分组。
- **违反的后果**：**结论无效** —— 修正收益被归给错误的机制；不确定性被重复或漏算，区间语义不成立。
- **语料反例（带 key）**：`3942513879_2247502947_1` —— 该篇被明确点出：Kalman 不是"把预测值和真实值取个平均"，必须说清修正的是结构状态还是预测偏差，并要求"只有偏差确实具有可建模的时间相关性，动态偏差修正才可能带来收益"；同一篇的另一条是"避免不确定性重复计算：Kalman 的协方差与贝叶斯参数不确定性必须职责分明"，对应到 fem 场景即"求解器离散误差、代理模型误差、标签噪声三类不确定性不能混算"。
- **关联**：`P1-05`（离散化不确定性随样本携带）提供其中一类不确定性的量化；`P8-05`（提升不得外推）约束收益的表述。

### P8-05 · 提升幅度不得外推为可迁移结论

- **类别 / 强度 / 适用模式**：`SCOPE` · `MUST` · `both`
- **机理**：提升幅度由**实验设定**决定：基线的可修正性、数据生成方式、噪声水平。若基线本身与数据生成器同构，其误差几乎只剩"可修正的持续偏差 + 观测噪声"，修正模块自然收益巨大；换成一个误差主要来自不可预测噪声的真实基线，相对收益会小得多。把设定产物说成方法属性，是最容易被后续工作打脸的一类断言。
- **工程落地**：结果句固定写成"该修正范式**在此设定下**有效"，并附一行"设定敏感性"：基线换成更强/更接近真实的一路时，收益预期如何变化。合成数据上的结论必须标注"合成数据"。
- **判定方式**：人工判据 —— 报告中每处收益数字后存在设定限定词；断言合成数据场景的结论句含"合成数据"字样。
- **违反的后果**：**结论无效** —— 读者会把"在这个玩具设定下减半"读成"该方法通常能减半"，据此投入资源。
- **语料反例（带 key）**：`3942513879_2247502947_1` —— 基线是与数据生成器同构的 oracle 模型：真值 `baseline = X @ [2.0, 0.008, 0.6, 0.2]`，而基线回归用的基函数恰是同一组 `[1, t, sin(2πt/30), cos(2πt/30)]`，于是"MAE 减半"是这一设定的产物，不能外推为"Kalman 通常能把 15 天预测误差减半"；`3942513879_2247501471_1` —— 基于自造合成数据（趋势+周期+体制变化+尖峰）的教学示例，"注意力集中在窗口末尾""误差近似高斯"等结论是合成数据性质决定的，不可外推到真实业务数据，引为经验时必须标注"合成数据"；`3942513879_2247501933_1` —— 该篇的经验建议无代码、无数据、无统计检验，不能作为方法学依据引用。
- **关联**：`P0-06`（不得把标题当依据）是同一纪律在输入端的形式；`P6-07`（显著性）保证"有效"这个词至少是真的。

### P8-06 · 禁止全局静音警告

- **类别 / 强度 / 适用模式**：`ENG` · `MUST` · `both`
- **机理**：`warnings.filterwarnings("ignore")` 会同时掩盖收敛失败、参数无效、除零、特征名冲突等**功能性告警**。这些告警正是"结果不可信"的最早信号；静音之后，失败的拟合会安静地输出数值，并被写进结果表。
- **工程落地**：删除全局静音；需要降噪时按消息/模块精确过滤，并把被过滤的告警类别列入产物清单。收敛类告警（如 statsmodels 的 ETS 阻尼参数、LightGBM 的早停 API 变更）必须在日志中保留一次记录。
- **判定方式**：可机检（正则）—— 检索 `filterwarnings\(\s*["']ignore["']`，命中即判不通过；断言日志中收敛类告警至少出现过或被显式记录为"无告警"。
- **违反的后果**：**结论无效** —— 未收敛的拟合以正常结果的形式进入报告；问题在整条链路的末端才暴露。
- **语料反例（带 key）**：`3942513879_2247500204_1` —— `warnings.filterwarnings("ignore")` 全局静音会掩盖 statsmodels/XGBoost 的收敛与参数告警；`3942513879_2247500589_1` —— 全局静音掩盖了 statsmodels 的收敛警告（ETS 的阻尼参数是否收敛不得而知）。
- **关联**：`P9-05`（过程量落盘）提供告警的去处；`P5-04`（收敛判据）是本条要保护的诊断量。

### P8-07 · 区间/误差带只能用留出历史估计

- **类别 / 强度 / 适用模式**：`ENG` · `MUST` · `both`
- **机理**：用测试集真值残差的标准差去构造上线区间，等于把答案写进上线口径 —— 离线看起来校准良好，上线后立刻失效，而且这种乐观偏差**无法通过任何后续检查发现**（因为构造口径本身就是评估口径）。
- **工程落地**：区间的尺度参数只能来自训练段或验证段的残差统计；上线后按滚动窗口用**已经观测到**的残差更新（严格因果），更新频率与窗口长度写进契约。
- **判定方式**：可机检 —— 断言区间参数的计算索引 ⊆ train∪valid 索引；断言代码中不存在 `(y_test - y_hat)` 参与区间构造；断言上线更新逻辑只用历史观测。
- **违反的后果**：**指标虚高且上线失效** —— 离线的覆盖率达标是构造出来的；上线后覆盖率崩塌且原因不可见。
- **语料反例（带 key）**：`3942513879_2247501298_1` —— 置信区间用测试集真值残差的 std 计算（`res_std = (y_test - y_hat).std()`），属于用测试集构造上线口径，隐含乐观偏差；同一篇还有一处泄漏高危点：SARIMA 在训练集拟合却对全样本取 `get_prediction(...)`（含测试段），作者注释称"一步预测（滚动方式）"，但测试段本就无观测可用，这段预测的语义在代码与注释里都不明确；`3942513879_2247500784_1` —— 训练段估计的滚动标准差被外推到测试段形成恒定带宽（同时违反 `P6-12`）。
- **关联**：`P2-02`（选择只能用 train/valid）在区间构造上的具体化；`P6-12`（带宽随 horizon）是它的形状约束。

## 11. P9 · 可复现与工程记录

**本阶段的目标与出口物**：让"同一份代码第二次运行得到同一个数"成为可核对的事实；出口物是运行记录（版本、种子、命令、数据哈希）+ 过程量日志 + 一份"契约每一栏的执行状态"表。

### P9-01 · 四种随机源与确定性开关必须固定并记录

- **类别 / 强度 / 适用模式**：`REPRO` · `MUST` · `both`
- **机理**：随机性来自多个独立来源：Python `random`、NumPy、框架（torch/tf）、以及采样器（`DataLoader(shuffle=True)`、worker 进程）。只固定其中一个，其余仍会引入不可复现；在 GPU 上还需要确定性开关（如 cudnn 确定性算法）才能让同一种子在同一硬件上稳定复现。
- **工程落地**：写一个 `set_seed(seed)` 统一设置四类源，并在产物里记录库版本与 `cudnn.deterministic` 取值；`DataLoader` 显式传 `generator` + `worker_init_fn`。种子值必须出现在结果表里（见 `P9-03`）。
- **判定方式**：可机检 —— 断言 `set_seed` 覆盖 `random.seed` / `np.random.seed` / `torch.manual_seed` / `torch.cuda.manual_seed_all` 四处；断言采样器构造处传入了 `generator`；断言同种子两次运行的最终指标逐位相同。
- **违反的后果**：**不可复现** —— 全部结论在严格意义上不成立；调参结果无法归因给配置变化还是随机波动。
- **语料反例（带 key）**：`3942513879_2247500589_1` —— torch 无随机种子（只有 `np.random.seed(42)`）⇒ `DataLoader(shuffle=True)` 与 LSTM 初始化都不可复现，而 LSTM 又处在整个融合链的末端，因此该文全部 Hybrid 结论在严格意义上是不可复现的；`3942513879_2247500204_1` —— 未设置 `torch.manual_seed`，Transformer 结果不可复现（同批其他篇都设了）。
- **正例（带 key）**：`3942513879_2247500289_1` —— `set_seed(2024)` 同时设了 `np.random.seed` / `random.seed` / `torch.manual_seed` / `torch.cuda.manual_seed_all`（四个随机源都覆盖了，比本批其他篇规范），但**未设 `torch.backends.cudnn.deterministic`**，GPU 上仍有非确定性可能；`3942513879_2247501437_1` —— rng/KMeans 种子齐全并打印子簇数/权重和/样本数做自检。
- **关联**：`P9-03`（多种子区间）要求种子可枚举；`P4-07`（同种子消融）依赖本条成立。

### P9-02 · 库版本与关键 API 变更点必须写入产物

- **类别 / 强度 / 适用模式**：`REPRO` · `MUST` · `both`
- **机理**：同一个函数名在不同大版本下语义或签名会变（如 `early_stopping_rounds` 的位置在 lightgbm ≥ 4.0 已变更；`t-SNE` 的 `n_iter` 已废弃）。照抄代码跑不出同样结果时，最费时的排查对象就是"我到底装的是哪个版本"。版本是可复现性的一部分，不是环境噪声。
- **工程落地**：运行开始时把关键库的 `__version__` 写入产物（`env.json`）；对任何在版本间变更过签名的调用，在注释里标明最低版本；在 fem 模式下同一条纪律扩展到**求解器溯源**：solver 版本、输入文件、网格分辨率随样本记录。
- **判定方式**：可机检 —— 断言产物含 `env.json` 且包含至少 sklearn / numpy / 框架三项版本；断言样本元数据含求解器版本与输入文件标识（fem 模式）。
- **违反的后果**：**不可复现** —— 复现者拿到不确定的差异，无法区分"环境不同"与"代码不同"。
- **语料反例（带 key）**：`3942513879_2247501029_1` —— `early_stopping_rounds` 的参数位置在 lightgbm ≥4.0 已变更，且未给库版本，这是"照抄代码跑不出同样结果"的经典原因；`3942513879_2247501394_1` —— 工程细节坑：全局单 optimizer 贯穿预训练与微调、无早停/无 scheduler、MMD 的 sigma 硬编码、t-SNE 用已废弃参数名 `n_iter`，写训练脚本前应在契约里固定优化器/调度/早停与依赖版本；`3942513879_2247500784_1` —— 版本号未给（numpy/pandas/scipy/scikit-learn/matplotlib/seaborn 均未注明）。
- **关联**：`P9-01`（种子）与它一起构成"运行指纹"；`P1-05`（离散化不确定性）在 fem 模式下依赖求解器溯源。

### P9-03 · 单点不算结果：报多种子/多折区间与胜率

- **类别 / 强度 / 适用模式**：`REPRO` · `MUST` · `both`
- **机理**：单次运行的指标是**一个样本**，它的方差来自初始化、数据顺序、采样，量级常常大于被比较方法之间的真实差异。因此"跑一次拿最高分即宣布成功"不仅不可复现，而且系统性偏向乐观 —— 它是在分布上取极值。
- **工程落地**：每个候选配置至少跑 3 个种子（或 5 折），报告均值 ± 标准差或区间；方法对比用配对设计并按 `P6-07` 的格式给出 Δ、CI、胜率。禁止只报最好一次的结果；若受算力限制只能跑一次，必须在产物里写"n=1，未估计方差"。
- **判定方式**：可机检 —— 断言结果表含 `n_runs` 字段且 ≥ 3（或带 `n=1` 标记）；断言同一配置存在多条种子记录；断言没有"只保留 max"的行。
- **违反的后果**：**指标虚高** —— 报告的是 best-of-N 而非期望表现；后续比较全部建立在极值上。
- **语料反例（带 key）**：`3942513879_2247502382_1` —— 该篇明确反对"只挑最好的 seed 写进论文"，并给出可判定格式（30 次里 27 胜、CI 不跨 0 才可信；17 胜 13 负、CI 跨 0 就不可信）；`3942513879_2247501205_1` —— 本文只给了单折、单种子的 Accuracy=0.994，且 KMeans 与 GMM 只有图形对比没有量化对照；`3942513879_2247502133_1` —— 无验证集、无多种子、无基线对照，标题结论在本篇里没有证据支撑。
- **关联**：`P6-07`（显著性判定）是它的报告格式；`P4-07`（同种子消融）是它的执行前提。

### P9-04 · 改真值/样本量必须同步所有引用处；报告数值必须从产物读出

- **类别 / 强度 / 适用模式**：`REPRO` · `MUST` · `both`
- **机理**：手写数字与脚本输出是两份独立的事实来源，一旦代码改动（样本量、划分比例、清洗规则），正文里的手写数字不会同步更新。这类不一致**读起来完全正常**，只能靠对账发现；而它一旦被发现，整篇的数字可信度都会受质疑。
- **工程落地**：报告中的所有数值通过模板从结果文件注入（生成脚本），禁止手写；每次改动数据规模/真值后，跑一次"数值对账"：结果文件中的每个数字与报告中的每个数字一一比对。样本量、划分比例等元信息同样从产物读取。
- **判定方式**：可机检 —— 断言报告由脚本从结果文件生成（存在模板 + 生成命令）；断言报告中的每个数字都能在结果文件中找到同名条目；断言正文与代码的样本量字段一致。
- **违反的后果**：**不可归因 + 结论反转** —— 读者按错误的样本量理解指标；"结论"可能只对应一个不存在的实验配置。
- **语料反例（带 key）**：`3942513879_2247500530_1` —— 正文举例数字与真实图不符：第 06 节文字说"前2个主成分解释了 65%、前3个 82%、前5个 93%"，而图 2 实际是 0.44 / 0.57 / 0.75，是典型的"图是跑出来的、正文数字是手写的"事故；`3942513879_2247501265_1` —— 正文说序列长 250、后 50 点测试，代码却是 length=300 → 测试集 100 点，文字与代码不一致；`3942513879_2247500352_1` —— 同一批内的推广数值自相矛盾（原文最重要的可核验发现）。
- **关联**：`P6-08`（指标必须落文）是它的前置；`P10-04`（图注与代码核对）是它在图侧的同一动作。

### P9-05 · 过程量与自检量必须打印并落盘

- **类别 / 强度 / 适用模式**：`REPRO` · `SHOULD` · `both`
- **机理**：中间量（样本数、权重和、子簇数、收敛步数、评估奖励、被排除样本数）是判断"运行是否按预期发生"的唯一证据。只收集不汇总的中间量在流程上等于不存在 —— 例如收集了 `eval_rewards` 却从未汇总，就无法发现策略没有变好。
- **工程落地**：约定一组自检打印并写入日志：数据规模与切分规模、类别/数量分布、被排除样本数及原因分布、收敛步数、关键中间量的极值与均值。日志与产物一并归档。
- **判定方式**：可机检 —— 断言日志文件存在且含约定的自检字段；断言代码中不存在"只 append 从不 aggregate"的收集器（如 `eval_rewards`）。
- **违反的后果**：**不可归因** —— 运行是否有效无法判断；失败会被读成成功。
- **语料反例（带 key）**：`3942513879_2247500289_1` —— 测试段的 `eval_rewards` 只被收集、从未被汇总，且训练奖励只记录不评估；`3942513879_2247500115_1` —— 评价指标只在 stdout 出现，正文完全没有数值。
- **正例（带 key）**：`3942513879_2247501437_1` —— 打印子簇数/权重和/样本数做自检，语料称"这套 print 自检值得照搬进契约的可复现性栏"。
- **关联**：`P5-04`（收敛判据）与 `P5-06`（预算匹配）都依赖这些量可读。

### P9-06 · 契约里写了的一栏必须执行到（导入未用 = 未做）

- **类别 / 强度 / 适用模式**：`REPRO` · `MUST` · `both`
- **机理**：写了却未执行的条款比不写更危险 —— 它让评审者以为该步骤已经完成（"用了 `TimeSeriesSplit`""加了缺失指示变量""跑了网格搜索"）。代码里"已导入、已定义、已注释"都是**意图**，不是执行。执行与否只能由调用点与输出来判定。
- **工程落地**：契约每一栏对应一个产物或一条调用记录，交付前逐栏核验，状态取 `done` / `skipped + reason`。删除未使用的导入，避免制造"考虑过"的假象。
- **判定方式**：可机检 —— 断言每个契约条目有状态字段；断言存在"已定义但从未被调用"的关键函数/类（静态检查可发现）；断言没有未使用的模型类导入。
- **违反的后果**：**结论无效** —— 报告的流程与实际流程不一致；"已做过交叉验证/已处理缺失"等陈述不成立。
- **语料反例（带 key）**：`3942513879_2247501298_1` —— `TimeSeriesSplit` 导入即弃；`3942513879_2247501265_1` —— 代码 import 了 `GridSearchCV` 却从未使用，ARIMA 阶数与 RF 超参全部写死；`3942513879_2247500799_1` —— `RandomForestClassifier` import 了但未使用，正文反复讲"树模型更鲁棒"却没有跑任何树模型；`3942513879_2247500069_1` —— "加入缺失指示变量"被列为答法第 5 条，代码里并没有真的加。
- **关联**：`P4-03`（承诺的对照不算基线）是它在基线栏的实例；`P9-07`（死代码）是它的邻近问题。

### P9-07 · 死代码与未生效分支必须删除或显式标注

- **类别 / 强度 / 适用模式**：`REPRO` · `MUST` · `both`
- **机理**：保留但未生效的代码会造成两种误读：读者以为该逻辑参与了结果（如逆标准化），或读者以为某个实现细节（如对全部节点求平均）与实际不同。前者污染数值解释，后者让同一张图对应两种互斥的解释。
- **工程落地**：交付前静态检查"定义了但从未生效"的分支（被注释掉的赋值、永假条件、未被引用的中间变量），删除或在近旁写"本段不生效，保留仅用于演示，结果为 X"。代码注释与实现的差异必须在同一轮修正。
- **判定方式**：可机检 —— 断言没有"被赋值但从未被使用"的关键变量（如 `y_pred_s*y_std+y_mean` 的结果未被后续使用）；断言注释中描述的行为与代码一致（抽查关键函数）。
- **违反的后果**：**不可归因** —— 数值偏移的来源无法定位；同一张图可以被两种互斥解释覆盖，结论不成立。
- **语料反例（带 key）**：`3942513879_2247500676_1` —— 逆标准化代码保留但实际未生效（`y_pred = y_pred_s * y_std + y_mean` 把已经未缩放的预测又乘又加），代码注释承认这段是死代码，语料注为"这很可能是系统性偏移的来源"；`3942513879_2247500364_1` —— 代码注释与实现不一致（注释说"前几个节点"，代码是 `mean(axis=0)` 全部节点），使"注意力确实退化为查询无关"与"对 30 个节点求平均后抹平了差异"两种解释无法区分。
- **关联**：`P9-06`（写了要做）是它的正向形式；`P8-01`（上线复用参数）最容易被死代码破坏。

## 12. P10 · 交付与证据

**本阶段的目标与出口物**：让每一句结论都能在自己的输出里被指认；出口物是图件集（含判据与读数）+ 结果表 + 一份对账记录（正文数值 ↔ 结果文件 ↔ 图面）。

### P10-01 · 每条断言必须能在自己的输出里指出证据；读不出就写"未观察到"

- **类别 / 强度 / 适用模式**：`EVIDENCE` · `MUST` · `both`
- **机理**：图注与正文的断言若指向图中不存在的结构，读者无法复核，错误会一直传下去。反过来，读不出结论时必须如实写"未观察到"，而不是套用通用话术 —— 通用话术会把"没有信息"包装成"符合预期"。
- **工程落地**：交付前逐条核对：正文/图注的每个断言（数字或可见结构）在对应图件或结果文件中可指认。不可指认的两种处理：改写成可指认的句子，或改写为"未观察到 X"。禁止使用"偏上=高估/偏下=低估"这类模板段落代替实际读数。
- **判定方式**：人工判据（逐条）—— 抽查每张验收图至少一条断言；断言无法指认的条目数为 0。可机检辅助：报告中的每个数字都能在结果文件中找到（与 `P9-04` 联动）。
- **违反的后果**：**结论无效** —— 关键改进只存在于图注里；读者据一个不存在的现象做决策。
- **语料反例（带 key）**：`3942513879_2247501612_1` —— 4 张诊断图全部与正文给出的解读相反或不可支撑（损失曲线首个 epoch 出现 8e9 量级爆炸、注意力热力图是按 Key 位置坍缩的三条竖带、四个头的距离分布几乎完全重合、t-SNE 三类完全混杂而无簇、逐步误差 ≈255 且不随步数增长），说明"图都画了" ≠ "结论有据"；`3942513879_2247501084_1` —— 改进只存在于图注（损失钉在 ln2、准确率 0.49–0.55，正文却称 LSTM/GRU 打赢 RNN）；`3942513879_2247501302_1` —— 11 张技术配图正文一句解释都没有，读者拿不到图里的任何结论。
- **关联**：`P5-05`（把判据套用到自己的图上）是它在训练期的前置；`P10-04`（图注与实现核对）是它的机械检查项。

### P10-02 · 图上模型 = 报告模型

- **类别 / 强度 / 适用模式**：`EVIDENCE` · `MUST` · `both`
- **机理**：诊断图（边界、重要性、PDP、混淆矩阵）必须由**被报告的那个模型**产生。若为了画图方便换了一个轻量配置（更浅的树、只取前几个特征、另一组重采样），图证明的就是另一个模型；而读者会把两者视为同一件事。这类错误让证据链断裂且极难发现。
- **工程落地**：绘图函数从结果表里取模型标识（配置哈希/名称），并在图标题里打印该标识；出图后做一次核对：图标题的配置 == 结果表中该模型的配置。
- **判定方式**：可机检 —— 断言每张诊断图的标题含模型标识；断言该标识在结果表中有对应行且超参一致。
- **违反的后果**：**结论无效** —— 机制结论与指标不对应；读者会认为"报告的模型具有图上的性质"。
- **语料反例（带 key）**：`3942513879_2247500806_1` —— 图 1 用 `max_features=1`、只取前 2 个特征重训的模型去论证"随机森林更稳"，边界平滑主要是投票 + 特征子集退化的结果，不能直接外推到 8 维主模型；`3942513879_2247501901_1` —— 画特征重要性/PDP/混淆矩阵所用的 `best_model` 正是 **NoSampling**，而正文预告的是 ModerateSampling 更稳；`3942513879_2247501341_1` —— 文章的名称与实现不符（正文说 SoftXGBoost 每一步拟合前一轮残差、代码却是端到端 MSE 反传；正文说引入正则项、代码里 MSELoss 无任何正则；正文说随机森林靠 Bootstrap 抽样造树、代码里 10 棵树共用同一份数据没有重采样）。
- **关联**：`P7-04`（投影图必须声明近似）要求把"画图用的是什么模型"写在图上；`P10-04`（图注与代码核对）是同一动作的文字版。

### P10-03 · 坐标轴/色标范围必须可判读，并在交付时记录数值范围

- **类别 / 强度 / 适用模式**：`EVIDENCE` · `MUST` · `both`
- **机理**：极值会把坐标轴拉爆，使其余数据的差异被压平到看不见。此时图**形式上存在、信息量为零**，但它在报告里占用"已检查过分布"的位置。色标同理：把极小差异映射到全部色域会制造虚假反差（见 `P7-03`）。
- **工程落地**：出图前检查"纵轴范围 vs 数据范围"比值；对比类图考虑对数纵轴或分段展示；每张验收图记录坐标范围与关键分位数。分布对比图若某组被压缩成贴地细线，必须拆子图或改用分位数坐标。
- **判定方式**：可机检 —— 断言每张验收图的元数据含 `xlim/ylim`（或分位数记录）；断言对比图中各组的可视高度差不为 0（人工抽查）。
- **违反的后果**：**无法归因** —— 读者得到"看不出差异"的结论，而真实差异可能很大（或相反）。
- **语料反例（带 key）**：`3942513879_2247500520_1` —— 图 1 KDE 因 None 的量纲达 ±5000，x 轴被迫拉得极宽，其余三条曲线被压缩成 x≈0 处的一条竖直尖峰，完全看不出分布形状；`3942513879_2247500546_1` —— 图 5 的纵轴被 degree=10 的 116,000 拉爆，导致前 8 阶的差异被压平在 0 附近，图的对比功能实际失效（语料注为连续第 3 次出现同类问题）；`3942513879_2247500059_1` —— income 的小提琴被一根从 0 直插到约 23 万的长尾拉爆；`3942513879_2247500415_1` —— 左面板 6 个特征里 4 个退化成贴着 y=0 的窄横条，只有两个横扫且离群点把 y 轴拉到 ±2000 以上。
- **正例（带 key）**：`3942513879_2247500327_1` —— "累计方差曲线 + 阈值线 + k 竖线 + 高亮散点"四件套把"为什么选这个 k"固定在图上，读者无需相信正文的口头解释。
- **关联**：`P0-02`（逐通道量纲声明）解释这类失效的成因；`P7-03`（均匀基线）是色标版本的同一问题。

### P10-04 · 图注/标题与代码实现必须逐行核对（凡自称"改了 X"的文章优先核对）

- **类别 / 强度 / 适用模式**：`EVIDENCE` · `MUST` · `both`
- **机理**：正文描述的是作者的意图，代码描述的是实际发生的事，两者分叉时只有代码有效。这一点在"自称做了某项改进"的叙述里风险最高：作者已经认为自己做了，因此不会再去核对；而读者会把"声称"当作"已做"。
- **工程落地**：交付前做一次"声明—实现"对照表：把正文/图注里的每个动作性声明（加了缺失指示变量、用了 Bootstrap、加了正则、改了阈值、做了早停）与代码里的对应实现逐一核对；核对不上的要么补实现，要么改文字。
- **判定方式**：可机检（配合人工）—— 对照表存在且每行有 `claim / evidence / verdict`；断言 verdict 不存在 `unmatched` 未处理项。
- **违反的后果**：**结论无效** —— 方法描述与实际不符；复现者照着文字做不出同样的结果。
- **语料反例（带 key）**：`3942513879_2247501341_1` —— 名称与实现不符的三处（SoftXGBoost 残差拟合、正则项、RF Bootstrap 抽样）；`3942513879_2247500069_1` —— "加入缺失指示变量"被列为答法第 5 条，代码里并没有真的加；`3942513879_2247501265_1` —— 正文说序列长 250、后 50 点测试，代码是 length=300 → 测试 100 点。
- **关联**：`P9-06`（写了必须执行）与 `P9-07`（死代码）是它在工程侧的形式；`P0-06`（不得把标题当依据）是它在引用侧的形式。

### P10-05 · 图上先写判据，再写读数

- **类别 / 强度 / 适用模式**：`EVIDENCE` · `SHOULD` · `both`
- **机理**：先写判据（"训练降/验证升 ⇒ 过拟合"、"对角线亮=近期"）把图变成**可被他人检查的对象**：任何人都能判断读数是否与图一致。判据写在图之后，则它只是对已选结论的追认，无法约束作者。
- **工程落地**：每张诊断图两行读法：`判据：…`、`读数：…`；读数必须落到数字或可见结构，并写出由此得到的一句话结论。超参/维度选择类图必须在图上标出决策点（阈值线 + 选定值）。
- **判定方式**：可机检 —— 断言图上或图注含"判据"与"读数"两段；断言选择类图含决策点标注（如 k 竖线、阈值虚线）。
- **违反的后果**：**结论反转** —— 图与结论相反时无人能及时发现；错误被"图已经画了"掩盖。
- **语料反例（带 key）**：`3942513879_2247500971_1` —— 作者写下了正确判据却没有把判据套用到自己的图上（该图为"原文自己没发现的错误"最干净的一例）。
- **正例（带 key）**：`3942513879_2247500364_1` —— 图 4 写"train/val 同步下降 = 稳定规律"、图 6 写"对角线亮=近期、远处亮=长程"；语料注为"无论图是否支持结论，先把判据写在图上这个习惯应当保留 —— 本批多篇都是因为判据写清楚了，才能被检查出结论与图相反"；`3942513879_2247500327_1` —— 选择 k 的四件套固定在图上。
- **关联**：`P5-05`（把判据套用到自己的图上）是它的执行；`P10-01`（断言可指认）是它的验收。

### P10-06 · 分解/加性图必须做"分量之和 == 总量"的自检

- **类别 / 强度 / 适用模式**：`EVIDENCE` · `MUST` · `both`
- **机理**：分解图的正确性有一个**免费的硬判据**：各分量相加必须等于总量。这条检查不需要真值、不需要额外数据，写一行断言即可。加性融合还额外存在"分量互相打架"的问题（周期性外推与均值回归方向相反），必须由权重校准来消解，而权重与分量的和一致是它的最小验收。
- **工程落地**：出图后立即断言 `abs(sum(components) − total).max() < tol`；加性融合的权重写进产物并检查 `w_i ≥ 0、Σw_i = 1`（或其等价的等权声明）。
- **判定方式**：可机检 —— 断言脚本中存在分量和自检；断言融合权重已记录或已声明为等权。
- **违反的后果**：**结论无效** —— 分解图无法支撑"分解"这一核心主张；读者会按错误的分量幅度理解模型贡献。
- **语料反例（带 key）**：`3942513879_2247500727_1` —— 图 6 的"预测分解图"画错了：`y_pred_total = y_glm_hat_future + y_pred_res`，图上"Prophet 风格部分"却贴在 y ≈ 0 而非其真实幅度（10–57），这张图因此无法支撑"分解"这一核心主张；`3942513879_2247500589_1` —— 组件模型（Prophet/ETS）的周期性外推与残差模型（LSTM）的均值回归会互相打架，加性融合必须做权重校准（本文把它列为"增强策略"而没做），代码真正跑的是等权退化版。
- **关联**：`P8-04`（修正对象声明）与它在"分量含义"上互补；`P10-02`（图上模型 = 报告模型）保证分量来自同一模型。

### P10-07 · 图例与面板标签必须可见且与面板一一对应

- **类别 / 强度 / 适用模式**：`EVIDENCE` · `MUST` · `both`
- **机理**：多面板图依赖标题/图例来区分面板；一旦标签不可见（白字白底、被裁切）或缺失，读者只能靠正文叙述顺序去猜哪个面板对应哪种设置。此时图不再承载独立信息，任何"面板间对比"都建立在猜测上。
- **工程落地**：出图后检查每个面板的标题/图例可见（对比度、未被 `tight_layout` 裁切）；图例项与应用到的曲线数量一致；若发现某条曲线缺失或被覆盖，必须查明原因（重合 / 绘图丢失 / 图例裁切）并**如实记录**，不得默认它不存在。
- **判定方式**：可机检（视觉抽查 + 元数据）—— 断言每个面板的 title 非空且字体颜色与背景对比；断言图例项数 == 绘制的曲线数。
- **违反的后果**：**无法归因** —— 面板与策略的对应关系不可判定；跨面板结论失效。
- **语料反例（带 key）**：`3942513879_2247502936_1` —— 所有 `color="white"` 的轴标题在白底上不可见，四个面板（原始分布/增强后分布、Loss 曲线/验证准确率、t-SNE 特征、混淆矩阵）全部无可见标题，读者无法从图上分辨哪个面板对应哪种策略；对照证据：同一批用 `plt.title()` 的图标题正常显示；`3942513879_2247500302_1` —— 图 7 只有一条曲线的成因未知（无法判断是后两条曲线被完全覆盖、绘图/保存环节丢失、还是图例被裁切），语料注为"我按'只辨认出一条'记录，不推断原因"。
- **关联**：`P10-03`（范围可判读）与它共同保证"图是可读的"；`P10-01`（读不出就写"未观察到"）规定缺失时的措辞。

### P10-08 · 跨图/跨面板比较必须同尺度同种子

- **类别 / 强度 / 适用模式**：`EVIDENCE` · `MUST` · `both`
- **机理**：分别拟合的降维/嵌入图各有自己的坐标系，"簇的紧密度、分离度"在不同面板之间不可比较；不同随机种子下的同类图连形状都不同。让它们并排出现，等于用视觉相似性替代了同一个度量 —— 读者会做出图上并不存在的比较。
- **工程落地**：跨面板比较必须使用同一个拟合对象（同一投影矩阵）、同一个随机种子、同一套坐标范围；若确实要并排，则在图上标注共同坐标范围，并在图注写明"各面板独立拟合，坐标不可直接比较"。
- **判定方式**：可机检 —— 断言跨面板图的投影对象为同一实例（或记录了共同的 `random_state`）；断言并排图的 `xlim/ylim` 一致。
- **违反的后果**：**结论无效** —— "增强后类间边界更清晰"之类的跨面板结论不被图支持，而图看起来支持它。
- **语料反例（带 key）**：`3942513879_2247502936_1` —— t-SNE 跨面板比较在方法上无效：三个面板各自独立拟合 t-SNE，坐标轴无共同尺度，面板间的"簇分离度/紧凑度"不可直接比较，且 val 仅 180 点、perplexity=30 偏大、少数类只有 16 点；`3942513879_2247500609_1` —— 五种玫瑰图各用不同种子，图间不可比（与"同一批样本 + 同一随机种子"的对照设计形成鲜明反差）。
- **正例（带 key）**：`3942513879_2247500661_1` —— 六组图（分布/相关/PCA/距离/KMeans/轮廓系数）全部基于同一份数据，因此每一组对比都可信。
- **关联**：`P4-07`（同切分同种子做消融）是它在实验设计侧的对应；`P10-03`（范围记录）使"是否同尺度"可被检查。

## 14. 本文件不声称什么

1. **不声称任何指标或方法的普适排名**。本文件给的是"在什么条件下该做什么、怎么判定"的程序性规则，不含"某模型更好"的结论；具体选型仍须由 `P4-06` 的机制对照表与本次实测决定。
2. **不声称语料中的经验已被独立验证**。全部 key 指向一个从业者公众号语料（`wechat-corpus/`），不是基准测试，多数条目是**单篇作者的自证或第三方阅读笔记的读数**；它们被收录是因为多轮独立阅读反复命中同一失效模式，不是因为它们在受控研究中被测量过。引用时按"需要核对的失效模式"使用，不要当成发生率或定量幅度引用。
3. **不声称覆盖全部 ML 工程纪律**。本文件的规则来自该语料与既有 references（`ml-evaluation-and-leakage.md` 等）的可溯源部分；语料未涉及或无法带 key 的主题（例如分布式训练、特征存储、模型服务的容量规划）本文件**故意不写**，而不是"已经覆盖"。缺失即未覆盖，不构成"可以不做"的许可。
